## 1. 무엇이 바뀌었나 — 한 줄

`extracted.json`의 **`future_task` 항목에 `ax_mentioned` 불리언이 하나 늘었다.** 끝이다.

```json
"future_task": [
  { "text": "...", "horizon": "장기", "ax_mentioned": true, "quotes": ["..."] }
]
```

**LLM 프롬프트는 바뀌지 않았다.** 값은 코드가 정규식으로 `quotes`를 훑어서 채운다
(`td_extract._AX_RE`). 그래서 **요청·응답 크기, JSON 파싱 실패율, 콜 수가 이전과 동일하다** —
#30(20kb 잘림) 계열 증상이 이번 변경 때문에 달라질 이유는 없다.

`td_cards`가 그 값을 카드까지 실어 나른다(`horizon`과 같은 복원 경로). 화면
(`td_inspect`·`td_roadmap`)은 **아직 이 값을 쓰지 않는다** — 눈에 보이는 변화가 없는 게 정상이다.

### 이 태그가 주장하는 것과 주장하지 않는 것

| | |
|---|---|
| 주장한다 | "이 과제의 **원문 인용에 AX/AI/ML/머신러닝 같은 표현이 실제로 적혀 있었다**" |
| 주장하지 않는다 | "이건 진짜 AI 과제다" — 실체 판정은 파이프라인이 하지 않는다 |

근거와 기각된 대안: `docs/adr/0001-ax-is-a-tag-not-a-category.md`.
용어는 `CONTEXT.md`.

## 2. 돌리기 전에 — `extracted.json`을 새로 만들어야 한다

기존 `extracted.json`에는 이 필드가 **없다.** 재추출하지 않으면 태그가 전부 비어 있고,
`td_cards`는 그걸 `false`로 읽는다 — **"AX 언급이 하나도 없다"와 구분되지 않는다.**

`AGENTS.md`는 `extracted.json`을 지우지도 `touch`하지도 말라고 한다. 그 규칙을 깨지 말고,
**이번 실행은 새 `TD_OUT_DIR`을 써라.**

```bash
export TD_OUT_DIR=/secure/run-sw-0825      # 기존 실행 디렉터리와 다른 경로
```

어차피 이번 실행은 대상 인원이 달라(3절) 산출물을 섞으면 안 된다. 새 디렉터리면
전 스테이지가 처음부터 깨끗하게 돌고, 기존 실행분은 그대로 남는다.

## 3. 이번 실행 스코프 — SW 조직만, 약 30명

파일럿이다. 부서 하나만 먼저 완주해서 수율을 본다.

**파이프라인에 `--pjt` 같은 필터 옵션이 없다.** 대상자만 담은 `persons.json`을 만들어
`--sources`로 넘겨라. 스키마는 [[task-discovery-pipeline-reference]] 1절 그대로이고
`id`는 0부터 다시 매겨도 된다(이후 전 스테이지가 이 `id`만 따라간다).

```bash
python3 scripts/td_pipeline.py $TD_OUT_DIR --sources <SW 30명 persons.json>
```

**30명이면 전 구간 대략 170콜이다** — 추출 30 + taxonomy 3~5 + assign 약 120 + narrate.
200명 기준의 6분의 1이라, 중간에 죽어도 재실행 부담이 작다. 죽으면 같은 명령을 다시
실행하면 이어간다(사이드카 재개).

> **모수가 작아서 생기는 것:** `td_aggregate`의 소수의견 문턱은 절대값 `WEAK = 2`다.
> 200명에서 2명은 1%지만 30명에서는 6.7%다. `minority`가 카테고리 대부분을 차지할 수 있다.
> **이건 고장이 아니라 예상된 것이다.** 숫자만 보고해라 — 문턱을 조정할지는 Claude Code 판단이다.

## 4. 확인하고 넘길 것

`td_peek.py` 출력만 넘긴다(`AGENTS.md` 규칙 1). 이번에 특히 볼 세 숫자:

```bash
python3 scripts/td_peek.py $TD_OUT_DIR/task_discovery
```

| 볼 것 | 왜 |
|---|---|
| `extracted.json` 무신호 건수 | 30명 중 몇 명이 신호 없음인지. 이게 크면 태그 이전에 추출이 문제다 |
| `assignments.json` Other 비율 | 20% 넘으면 taxonomy 품질 신호 |
| taxonomy 카테고리 수 | 30명 facet 90~120에서 몇 개가 나오나 (가이드는 15~25) |

### ⚠ `td_peek`은 `ax_mentioned`를 세지 않는다

이번 변경에 맞춰 `td_peek`을 고치지 않았다. **그래서 "태그가 몇 건 붙었나"를 넘길 창구가
지금 없다.** 직접 `extracted.json`을 열어서 세거나, 그 숫자를 손으로 옮겨 적지 마라 —
경계를 넘는다.

**이 숫자가 필요하면 사람에게 요청해라.** `td_peek`에 건수 한 줄을 추가하는 건
Claude Code가 할 일이고, 그건 정수 하나라 안전하게 노출할 수 있다.

### 넘기지 말 것 (평소와 같다)

- 실명·회고 원문·인용
- **카테고리명** — AX 관련 카테고리 이름도 포함이다. "AX 카테고리가 생겼다"는 사실은 넘겨도
  되지만 그 **이름**은 안 된다
- `calls/**`의 원본 프롬프트·응답

### 판단하지 말 것

`AGENTS.md` 규칙 2가 여기서도 그대로 적용된다. 특히 이번 건에서 넘기기 쉬운 판단:

| 사실 (넘겨도 됨) | 판단 (넘기지 말 것) |
|---|---|
| "태그된 카드가 N건이다" | "태그가 과하게 붙은 것 같다" |
| "AX 관련으로 보이는 카테고리가 생겼다" | "정규식이 잘못됐다" |
| "`inspect.html`에서 태그가 안 붙은 AX 과제를 봤다" | "그러니 프롬프트로 옮겨야 한다" |

마지막 줄이 특히 중요하다 — **태그가 놓치는 건은 설계상 예상된 것이다**(5절).
놓친 사례가 있다는 **사실**은 유용하고, 원인과 대책은 Claude Code가 코드를 읽고 정한다.

## 5. 알려진 한계 — 미리 알고 보면 놀라지 않는다

1. **태그는 `quotes`만 보고 붙는다.** 인용이 AX 표현 없는 다른 문장으로 잡히면 놓친다.
   의도된 누락이다 — 지어낸 태그보다 놓친 태그가 낫다는 판단이고, 놓친 쪽은 워크숍에서
   사람이 줍는다.
2. **taxonomy가 AX 카테고리를 만드는 것은 이 변경이 막지 못한다.** 태그는 카드 층 장치다.
   합성 실행에서 AX 카테고리 하나가 34명을 빨아들인 전례가 있다. **생기면 사실로 보고해라**
   (이름 말고 "생겼다"와 인원 수). 막는 지시를 taxonomy 프롬프트에 넣을지는 미결이다.
3. **화면에 안 나온다.** `td_inspect`·`td_roadmap`에 AX 필터가 아직 없다. 매트릭스에서
   어떻게 보일지가 미정이라 화면 작업을 하지 않았다.
4. **`capability_gap`에는 태그가 없다.** 키 자체가 없다(`false`가 아니라 없음). 의도적이다.

---

## 6. 되돌리기·고치기

정규식이 문제로 보이면 **`td_extract._AX_RE` 한 줄만** 고치면 된다. 다만 태그는 추출
시점에 박히므로 **추출을 다시 돌려야 값이 바뀐다**(30콜). `td_cards`부터 다시 돌리는 걸로는
안 된다.

태그 자체를 무르려면 두 곳(`td_extract._filter`의 분기, `td_cards`의 한 줄)을 지우면
되고 다른 스테이지는 이 필드를 읽지 않는다.

---

## 7. 이번 실행이 답해야 할 질문

파일럿의 목적은 AX 태그 검증이 **아니다.** 순서대로:

1. **30명 코호트에서 추출이 제대로 도나** — 무신호·폐기 비율
2. **taxonomy가 쓸 만한가** — `td_inspect`로 카테고리→항목→사람→원문을 걸어보고 판단
3. **그 다음에 AX 태그가 말이 되나**

1번이 안 되면 2·3번은 볼 필요가 없다. `td_inspect`를 assign 직후에 먼저 띄우라는
`AGENTS.md` 권고가 이번에도 그대로다.
