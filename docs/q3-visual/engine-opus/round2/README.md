# engine-opus round2 (재시도) — 「작업 현장」 (Workspace-first)

지시서는 `docs/engine-layout-round2-brief.md`이고, 구도는 재시도 프롬프트(`run-engine-opus-r2b.sh`)에서 받았다. 이전 커밋 15ab077 「초월적 여백」은 폐기했다. `nebula/templates/nebula.html`을 그 커밋 직전 상태(15ab077^)로 되돌린 뒤 live 레이아웃 CSS 블록을 새로 썼다. JS는 1줄만 고쳤다.

이 화면은 슬라이드가 아니라 작업 화면이다. 발표자가 300명 앞에서 별을 누르고, 검색하고, 다음 장면으로 넘긴다. 그래서 구도보다 조작 가능성을 먼저 봤다.

## 구도 원리 3줄

1. **클릭 반경이 줄어들면 실패다.** 지도는 발표자의 손이 닿는 화면 중앙~하단에 두고 기존 템플릿보다 크게 그린다. 1920×1080에서 과제 별의 클릭 반경은 10.4px에서 11.1px로 늘었다.
2. **UI는 지도의 이음매(seam)에 붙인다.** 장면 문장은 지도 윗변, PJT 선택·해제는 지도 윗변 띠, 범례·각주는 아랫변 띠, 검색·설명·숫자는 오른쪽 변 레일, 이전·다음은 아랫변의 정중앙에 있다. 지도 위에 뜨는 HUD는 없다.
3. **여백은 가장자리에만 조금 둔다.** 카드 바깥쪽 위아래 16px, 좌우 36px이 전부다. 이 여백은 커서가 화면 밖으로 미끄러지지 않게 하는 여유 공간이다.

## 이전 시도(「초월적 여백」) 대비 근본적 차이 3줄

1. **여백 실패의 교훈 — 여백은 클릭할 수 없는 영역이다.** 이전 시도는 화면의 60%를 비워 시선을 모았지만, 대가로 지도가 선 길이 기준 71%(889×534)로 줄고 클릭 반경이 10px에서 7.4px로 쪼그라들었다. 이번에는 비율이 아니라 클릭 반경을 먼저 고정하고, 남는 면적을 UI 띠에 나눠 줬다. 지도는 1337×802이고 이전 시도의 1.5배다.
2. **시선이 가는 방향이 반대다.** 이전에는 왼쪽 위 문장에서 오른쪽 아래 블록으로 시선을 대각선으로 멀리 보냈다. 이번에는 모든 요소가 지도 둘레 한 겹 안에 있어서 시선이 지도 중심에서 멀리 가지 않는다. 발표자가 가장 자주 누르는 `다음 →`은 지도 아랫변 중앙(x≈760, 지도 열 중심 760)에 있어서 커서와 관객의 시선이 같은 곳에 머문다.
3. **round1과 기존 템플릿은 "지도 + 떠 있는 UI", 이번은 "지도와 한 몸인 UI"다.** round1 후보는 지도를 키우고 툴바·범례·각주를 지도 위에 절대 위치로 띄웠다. 기존 템플릿은 헤더·단계 막대를 화면 위아래 끝에 붙였다. 이번에는 툴바와 범례를 지도의 윗변·아랫변 **띠**로 바꿨고, 검색창 높이(48px)를 툴바 띠와 맞춰 두 이음매가 한 선으로 이어진다. 헤더 행을 없애고, 브랜드는 문장 띠에, 읽는 법·전체 화면·합성 표시는 레일 아랫칸에 넣었다. 5컷 모두에서 지도 내용 영역과 겹치는 UI 상자는 0개다.

## 한계

- **지도 열 좌우에 빈 띠가 있다.** 지도는 높이에 맞춰 크기가 정해진다. 1920에서 지도 열은 1449px, 지도는 1337px이라 양옆에 약 56px 빈 띠가 남는다. 클로즈업에서 확대된 별은 이 띠까지 그려진다.
- **1366×768에서는 장면마다 지도가 약간 흔들린다.** 보조 문장이 장면 0·1에서 3줄로 접혀 문장 띠가 10px 높아지고, 배율이 0.700과 0.714 사이를 오간다. 1920·1600에서는 모든 장면의 배율이 같다.
- **장면 문장이 54px에서 44px로 작아졌다.** 문장이 hero가 아니라 지도 윗변의 띠가 됐기 때문이다. 문장보다 지도와 조작을 우선한 결과다.
- **단계 막대가 조작 버튼을 사이에 두고 둘로 나뉜다.** 순서는 왼쪽에서 오른쪽으로 읽히지만 한 줄로 이어진 진행 막대는 아니다.
- **설명 패널은 1920 기준 높이 약 760px이다.** 긴 근거 카드는 스크롤된다.
- 배지를 숨길 때 `:has()`(Chrome/Edge 105+)를 쓴다. 지원하지 않는 브라우저에서는 배지와 합성 표시가 둘 다 보이는 정도로만 달라진다.
- "UI가 지도와 겹치지 않음"은 viewBox 사각형과의 교차로만 판정했다. PJT 격자 칸·성운 이름·툴팁은 원래 지도 위에 있어야 하는 요소라 겹치는 게 맞다.
- 1920×1080, 1600×1000, 1366×768 세 크기만 확인했다. 폰트 스택은 기존 그대로다.
