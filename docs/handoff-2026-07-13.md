# Handoff: 실데이터 전처리 파이프라인 — 2026-07-13

## 상황 요약

실데이터(PPT→MD 변환본)로 persons.json 만드는 파이프라인을 완성했다. 첫 실행에서 **전원 `이상`** 증상이 났었는데, 원인은 두 가지였고 둘 다 해결됨:

1. MD 파일 맨 앞에 이름/PJT 등을 나열한 표가 있어서 `assign_pages`가 혼동됨 → 표 제거로 일부 해결.
2. 용량 문제로 분할된 `cl2_y5-8_1.md`/`_2.md`를 `cat`으로 합쳐서 처리하다가, 파일 경계(두 번째 파일의 `Page 0` 근처, 표지/목차 추정)에서 순차 핸드오프 로직이 이름 여러 명을 한 번에 건너뛰어 그 뒤 배정이 통째로 밀리는 문제 발생.

2번은 **`assign_pages` 재설계가 아니라 입력 프로세스 수정**으로 해결했다: `cl2_y5-8_1.md`/`_2.md`의 분할 지점은 항상 사람 단위로 깔끔하게 나뉜다는 걸 확인했고, `cat`으로 합칠 이유 자체가 없었다. 로스터에서 각자 실제 물리 파일명을 지정해 파일별로 따로 처리하면 인공적인 경계가 사라져 문제도 사라진다.

추가로 매니페스트 저장 포맷을 CSV → **sqlite**로 전환했다. 사내망 DRM이 `.csv` 파일을 가끔 걸어버리는 문제가 있었고(`.db`는 안 걸리는 것 확인됨), 겸사겸사 `master.json`(로스터)도 sqlite에 흡수시켜 **로스터 + 파이프라인 상태가 `roster.db`의 `roster` 테이블 하나**로 통합됐다.

## 완성된 부분 (커밋 대상)

### 스크립트 4개 + 테스트 3개

0. **`scripts/import_roster.py`** (신규) — `master.json` 로스터를 sqlite `roster` 테이블로 1회 이전
   - 입력: 로스터 JSON(객체 배열: seq/name/pjt/part/cl_level/source_file/source_file_seq)
   - 출력: `data/roster.db`의 `roster` 테이블 (로스터 필드 + 상태 필드: page_start/page_end/status/split_filename/normalized_filename)
   - `seq`를 PRIMARY KEY로 사용. 재실행 시 PK 충돌로 에러 나는 게 의도(실수로 중복 임포트 방지).
   - **이후 `master.json`은 폐기하고 `roster.db`를 직접 편집**(DB 툴 사용).

1. **`scripts/split_md_by_person.py`** — 결정론적 페이지 분할 (LLM 없음)
   - 입력: MD 파일 1개 + `roster.db`
   - 페이지 구분자: `<!--\s*Page\s+\d+\s*-->` (예: `<!-- Page 63 -->`, 소문자/공백 변형 허용)
   - `load_roster(conn, source_file)`가 `roster` 테이블에서 해당 md 파일 담당자만 필터링
   - 출력: 사람별 원문 md (`data/raw_sections/<pjt>__<part>__<name>.md`) + `roster` 테이블의 상태 컬럼을 `seq` 기준 `UPDATE`

2. **`scripts/normalize_person_text.py`** — LLM 정제 (사람별 마크다운 스키마)
   - 입력: 1번의 split 파일 + `scripts/llm.py`의 call 함수 주입
   - 프롬프트: PPT 발췌 지저분한 원문을 `# 근원경쟁력 / ## 핵심 역량 / ## 주요 경력 / ## 강점` 형식으로 다듬기
   - 출력: 정제본 md (`data/raw_sections/<pjt>__<part>__<name>.normalized.md`) + `roster.normalized_filename`을 `seq` 기준 `UPDATE`

3. **`scripts/merge_persons.py`** — 최종 조립
   - 입력: `roster.db` + `*.normalized.md`
   - 출력: `data/persons.json` (스키마: `{id, name, pjt, part, cl_level, text, tags:[]}`)
   - 정제 미완료자(`normalized_filename` 빈값)는 제외

## 파일 분할 시 지켜야 할 것

- `cl2_y5-8_1.md`/`_2.md`처럼 용량 때문에 분할된 파일은 **`cat`으로 합치지 않는다.**
- `roster.db`에서 이 그룹 인원들의 `source_file`을 물리 파일명 그대로 지정(`cl2_y5-8_1.md` 또는 `cl2_y5-8_2.md`).
- `split_md_by_person.py`를 물리 파일별로 따로 실행 — 같은 `roster` 테이블 안 각자 행이 `UPDATE`되므로 안전.
- 두 번째 파일이 `Page 0`부터 다시 시작하는 것도 무해함 — 각 실행이 자기 파일 안에서만 로컬 인덱스를 매기므로 파일 경계 자체가 사라짐.
- 같은 패턴(용량 초과로 분할)이 다른 그룹에도 있으면 동일 규칙 적용.

## 실데이터 특성

- **인당 페이지**: 3~6장 (여유있게 1~8을 정상 범위로, `MIN_PAGES`/`MAX_PAGES`)
- **이름 위치**: 페이지 하단
- **로스터 입력**: `data/roster.db`의 `roster` 테이블 (`master.json`은 `import_roster.py`로 1회 이전 후 폐기)
- **매니페스트 겸용**: 별도 CSV 없이 같은 `roster` 테이블에 상태 컬럼(page_start/page_end/status/split_filename/normalized_filename)을 얹어서 관리

## 남은 일 (다음 세션)

### 실행
1. `python scripts/import_roster.py <로스터 json 경로>` → `data/roster.db` 생성
2. `cl2_y5-8_1.md`/`_2.md` 각각에 대해 `split_md_by_person.py` 실행 (cat 없이)
3. `roster` 테이블에서 이 그룹 `status` 확인 — `이상` 행이 대폭 줄었는지 확인
4. 나머지 파일들도 순서대로 split → normalize → merge 실행

### 혹시 또 `이상`이 나오면
- `status='이상'`인 행을 눈으로 확인(page_start/page_end가 비정상 범위인지)
- 해당 md 파일에 페이지 구분자 누락/오탈자가 없는지, roster의 이름 표기가 md 원문과 정확히 일치하는지 확인
