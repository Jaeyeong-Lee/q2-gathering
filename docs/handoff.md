# Handoff: Heritage Archive 현재 상태 (2026-07-13 기준)

다음 에이전트/모델이 이 저장소를 이어받을 때 읽는 문서. **빌드·사용법은 루트 README가
정본**이고, 여기는 "왜 이렇게 생겼는지"와 함정을 남긴다.
(v1 핸드오프의 초기 요구사항 원문은 git 히스토리 `e30e847` 이전 버전 참조.
d3.js 계획은 폐기 — 실제 구현은 바닐라 캔버스 + ECharts(워드클라우드만)다.)

## 아키텍처 한 장

- **화면은 `archive/template.html` 단일 파일** — CSS/마크업/JS(IIFE 하나)가 다 들어있다.
  `scripts/build.py`가 여기에 데이터 JSON, echarts 2종, `cloud_logic.js`를 문자열 치환으로
  인라인해 `dist/heritage-archive.html`을 만든다. 마커: `/*__DATA__*/null`,
  `/*__FREQ__*/null`, `/*__ABOUT__*/null`, `<!--__ABOUT_PPT__-->`, `<!--__ABOUT_MD__-->` 등.
- **그래프 물리는 직접 구현** (repulsion + 스프링 + 중심 인력, Euler). d3 아님.
- `archive/cloud_logic.js`는 브라우저·pytest 겸용 순수 함수 모음. `cloudScopeIds`는
  화면에서 더는 안 쓰지만 **테스트가 있어 보존** — 지우려면 tests/test_cloud_logic.py도 정리.
- 필드명 주의: 파이프라인 스키마는 `pjt`인데 템플릿 JS는 `team`을 쓴다 —
  build.py가 `team=p["pjt"]` 별칭을 얹는다. `cl_level`도 노드에 `cl`로 복사됨.

## 인터랙션 모델 (여러 번 갈아엎은 끝의 최종형 — 이유까지)

**최종 규칙: "팀 클릭 = 그 팀만, 다시 클릭/빈 곳 클릭 = 전체" 하나뿐.**

- 처음엔 클릭=dim(부분 강조), 더블클릭=격리였다 → 사용자(Jay)도 못 외웠고,
  이건 발표 후 **아카이브로 남는 물건**이라 원클릭 단일 모델로 단순화 (`c0cc7f5`).
  230ms 더블클릭 판별 지연도 함께 사라짐. 습관성 더블클릭은 350ms 가드로 흡수.
- dim의 "훑어보는 재미"는 **범례 hover 순간 강조**로 대체 (상태 없음, 페이드 0.4).
- **CL 드롭다운은 그래프 필터** (범례 패널 상주) — `activeNodeList()`가
  팀×CL 교집합의 단일 소스. draw/히트테스트/검색 풀이 전부 이 함수를 쓴다.
- 워드클라우드: **소형(우하단) = 거시 참고용, 팀 필터만 반영·CL 무시.**
  **최대화(⛶) = 팀×CL 교집합** + 하단에 "필터: 팀 · CL (n명)" 표기.
  5명 미만 집합은 렌더 거부(프라이버시) — `cloud_logic.js CLOUD_MIN_PEOPLE`.
- 폐기된 것들: 스코프 탭(전체/팀별/CL별/유사군), 유사군 클라우드 자동 연동,
  "전체 팀 보기" 버튼. 전부 "필터 경로가 두 개면 헷갈린다"는 피드백으로 삭제.

## 물리/연출 튜닝 (숫자를 함부로 되돌리지 말 것)

- **빅뱅 인트로 폐기 → `warmUp(300)`**: 시드를 중앙 원반(반경 0.30)에 뿌리고
  첫 프레임 전에 tick 300회를 동기로 돌려(~50ms) 요동을 화면 밖에서 소화한다.
  팀/CL 필터 변경(`applyGraphFilter`)도 같은 워밍업을 탄다. 워밍업을 빼면
  로드/필터 때마다 노드가 폭발한다.
- **중심 인력 0.0003** (원래 0.0012): 크면 평형이 빽빽한 원반으로 붕괴.
  이전의 "예쁘게 퍼진" 화면은 사실 폭발 중간 장면이었다.
- **스프링 자연길이 `(1-w)*200+95`** (원래 `*180+34`): 더미 유사도가 0.85~0.97에
  몰려 있어 상수항이 실질 간격을 결정한다. 실데이터에서 유사도 분포가 넓어지면
  재튜닝 여지 있음 (todos/009의 유사도 정규화와 연동).
- **최대화 등장 연출 = CSS mask 원형 리빌** (중앙→바깥 1.8s). 색상 버킷별 웨이브를
  시도했다가 **폐기** — echarts-wordcloud는 data가 바뀌면 전체 재배치라 단어가
  웨이브마다 점프한다. 재배치 없이 순서감을 주는 유일한 방법이 마스크였다.
  단어 색은 빈도 순위 그라데이션(골드→틸), 단어별 등장 속도 노브는 플러그인에 없음.

## Behind the Scenes(설명 오버레이)

- 실데이터로 설명한다: build.py `build_about()`이 앵커 1명(`ABOUT_ANCHOR_ID`)의
  **실제 3072차원 벡터**(소수 3자리 반올림) + 전원 코사인에서 1위/중간/최하 3명 +
  top-K를 `/*__ABOUT__*/`로 주입. 화면 JS `drawVecStrip()`이 1×3072 히트맵으로 그린다
  (sqrt 감마 — 선형이면 거의 검게 보임).
- `archive/about/ppt.png`·`sample.md`를 놓고 재빌드하면 자동 인라인, 없으면 플레이스홀더.
- 이 오버레이의 문구/레이아웃(3컬럼, "How it Works" 등)은 Jay가 직접 다듬는 영역 —
  마크업 구조를 바꿀 땐 JS가 참조하는 id(anchorStrip, cmpRows, topkList 등)와
  null 가드를 확인할 것.

## 검증 방법 (함정 포함)

- **헤드리스 크롬은 반드시 `--headless=new`** — 구형 `--headless`는 echarts
  워드클라우드가 렌더되지 않아 "고장"으로 오판하기 쉽다(과거에 실제로 헛발질함).
- 스모크: `#view=cloudmax`, `#view=about`, `#ego=<id>` 딥링크 스크린샷 3장.
- pytest 29개 (.venv 사용, 시스템 python엔 pytest 없음). LLM 호출은 mock.
- 배포는 GitHub Pages(사내) 전제, 단일 인라인 HTML이라 `file://` 검증으로 충분 —
  **로컬 dev 서버 제안 금지** (사용자가 반복 지적한 사항).

## 실데이터 전환 시 체크리스트

1. persons/embeddings/freq 실데이터 재생성 → `similarity.py` → `build.py`
2. `ABOUT_ANCHOR_ID`를 PPT/md 표본 인물 id로, `archive/about/` 슬롯 채우기
3. 유사도 분포 확인 → 스프링 상수·min-max 정규화 재검토 (todos/009)
4. 무대 검색 후보 인물 사전 눈검수 (PRD US36)
5. 검색 placeholder "(150명)" 등 하드코딩 인원수 문구 확인

## 알려진 미세 이슈

- 에고 뷰 이웃 수가 Top-N 슬라이더 값에 묶여 있어(adjacency 기반) 슬라이더=5면
  궤도에 5명만 뜬다. 힌트 문구는 "상위 10명" — 불일치 인지 상태, 수정 보류 중.
- Top-N 슬라이더 변경은 워밍업 없이 alpha 0.5로 굴러간다(의도: 라이브에서
  밀도 변화가 보이는 게 데모 포인트).
