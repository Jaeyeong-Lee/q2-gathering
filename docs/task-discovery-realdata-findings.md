# task-discovery 실데이터 적용 — 품질 이슈 후보 정리 (2026-07-22)

실데이터로 처음 돌려본 결과가 기대에 못 미쳐서 원인을 짚어본 기록. 결론을 낸 문서가
아니라 **후보를 좁혀놓은 상태** — 다음 세션에서 검증부터 시작할 것.

## 증상 (실데이터 기준)

1. `extracted.json`의 `tasks[].text`가 거의 한 문장 수준 — `quotes`와 사실상 동일한
   텍스트로 나옴. 프롬프트는 "충실한 서술로 쓰라(여러 문장 허용)"고 요구했지만 반영 안 됨.
2. 과제 문장(~300개 추정: 150명 × 장/단기·복수 제안)을 임베딩→KMeans로 묶은 군집이
   눈으로 보기에 잘 안 묶인 것 같음 — 신뢰가 안 감.
3. 임베딩 모델이 README/설계 문서 기준 Gemini가 아니라 **내부망 BGE-M3**로 이미
   전환돼 있음(`EMBED_PROVIDER=internal` 계열, `llm.py`의 openai_compat 경로).

## 검토한 대안 — 항목 단위 → 사람 단위 추출

지금: 사람 1명 → 과제 항목 여러 개로 쪼갬 → 항목별 임베딩 → 항목 단위 클러스터링.

대안: 사람 1명 → "미래 업무에 해당하는 부분"을 통째로(장/단기 있으면 최대 2덩어리)
**찾아서 반환** — 의미 경계를 새로 발명하는 게 아니라 위치를 찾는 문제라 프롬프트
난이도가 낮고, quote 검증도 덩어리 하나 대조로 단순해짐. C의 근본 원인(포맷 자유도)을
우회하는 접근.

**미해결 질문**: 이 대안으로 가면 항목 수가 확 줄어드는데(150명 × ~1.5개 ≈ 225개가
아니라, 애초에 세분화를 포기하니 "장/단기 각 1개"가 상한), 지금의 "군집화→지도" 조직
방식을 그대로 쓸지, 아니면 더 가벼운 방식(태그, 목록)으로 대체할지 미정.

## 다음 액션 (우선순위 순)

1. **BGE-M3 한국어 sanity check** — 명백히 비슷한 과제 문장 vs 명백히 다른 문장
   몇 쌍을 직접 임베딩해 코사인 유사도 비교. D가 실제 원인인지 여기서 갈린다.
2. 1의 결과에 따라:
   - BGE-M3가 멀쩡하면 → A/B(프롬프트+검증) 먼저 고치고 항목 단위 유지 검토.
   - BGE-M3가 약하면 → 임베딩 모델 교체 또는 "사람 단위 추출" 대안(위 항목) 무게↑.
3. 어느 쪽이든 "군집화를 유지할지" 자체를 사람 단위 추출 검토와 묶어서 재결정.

## 검토 중인 방향 전환 — 온톨로지 기반 분류 (2026-07-23)

실데이터 산출물에서 클러스터가 도메인 용어를 뜬금없이 묶는 사례 확인(예: 설비 계열
용어와 무관한 "디지털 X" 계열이 한 군집에 섞임). BGE-M3가 사내 전문 용어를 일반
어휘와 구분 못 해서 벡터가 표면적으로만 가까워진 것으로 추정 — D/E 후보와 같은 축.
`run_pages`의 군집 요약 단계(PAGE_PROMPT)는 이미 묶인 결과를 설명만 할 뿐 교정하지
못하고, 오히려 안 어울리는 조합에 그럴싸한 제목을 붙여 문제를 가릴 위험이 있음(관찰됨).

**제안**: 비지도 클러스터링(임베딩+KMeans, 카테고리를 데이터가 알아서 찾음) 대신,
**미리 정한 카테고리 목록에 각 과제 문장을 분류**하는 방식으로 전환 검토. 분류는
임베딩 유사도가 아니라 LLM이 목록을 보고 고르는 방식이라 도메인 용어 무지 문제를
근본적으로 우회함. 부수 효과로 k(군집 개수)를 사람이 추측할 필요도 없어짐(F 후보
해소).

- **카테고리 목록 출처 후보 3가지** (미결정):
  1. 사람이 직접 작성 (도메인 담당자 검수)
  2. `scripts/freq.py`(Kiwi 명사 빈도, 이미 메인 아카이브 워드클라우드용으로 존재)로
     실데이터에서 자주 나오는 용어를 뽑아 초안 → 사람이 다듬기
  3. LLM에 실데이터 샘플을 보여주고 카테고리 후보 제안시킨 뒤 사람이 확정
- **기존 코드 앵커**: `task_discovery.py`의 `_DOMAINS`(:68~70, 더미 생성용 12개 목록)가
  사실상 즉석 온톨로지 스텁 — 실제 검수된 목록으로 교체하면 그대로 분류 기준표로
  전용 가능.
- **미해결 리스크**: 고정 목록이면 예상 못 한 새 주제가 "기타"에 뭉개질 수 있음 —
  분류 결과에 "기타" 비중이 일정 수준을 넘으면 목록을 갱신하는 절차가 필요할 듯
  (설계 미정).
