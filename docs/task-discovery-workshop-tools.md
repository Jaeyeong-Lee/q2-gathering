# 워크숍 도구 — 탐색기 · 로드맵 매트릭스 · 투표 서버

> 파이프라인이 끝난 **뒤에** 쓰는 화면 셋. 전부 `td_cards` 조인 위에 얹혀 있고,
> **LLM을 한 번도 부르지 않으며 새 의존성이 없다.** 산출물을 다시 만들어도 공짜다.
>
> 파이프라인 자체는 [[task-discovery-pipeline-reference]], 설계 근거는
> [[task-discovery-coldstart]], 사내망 운영은 [[task-discovery-internal-run-guide]].
>
> 작성 2026-08-10. 이슈 #37·#38(PRD) / #39~#45(구현 티켓, 전부 완료).
> 아래 예시는 전부 **합성 데이터**다.

---

## 1. 세 도구가 답하는 질문이 다르다

| 도구 | 답하는 질문 | 서버 | 언제 |
|---|---|---|---|
| **탐색기** `td_inspect` | "이 숫자가 어디서 왔지?" | 불필요 | 배정이 끝난 **직후**, 결과 검수 |
| **로드맵 매트릭스** `td_roadmap` | "전체가 어떤 모양이지?" | 불필요 | 워크숍 준비 · 진행자 1인 모드 |
| **투표 서버** `workshop_server` | "우리는 언제 할 건가?" | 필요 | 워크숍 당일, 참석자 각자 PC |

```
extracted · taxonomy · assignments · aggregates
                    │
              td_cards (조인)          ← 렌더링을 모른다
                    │
     ┌──────────────┼──────────────────┐
     ▼              ▼                  ▼
 td_inspect     td_roadmap      workshop_server
  탐색기         매트릭스 +        같은 화면 +
                카드 배치         투표 취합
```

**조인은 하나뿐이다.** 두 번 구현하면 언젠가 갈라진다.

---

## 2. 실행

전제: `$TD_OUT_DIR/task_discovery/`에 `extracted·taxonomy·assignments·aggregates.json`이 있다.

```bash
python3 scripts/td_cards.py       $TD_OUT_DIR/task_discovery      # 통계만 (건수 확인용)
python3 scripts/td_inspect.py     $TD_OUT_DIR/task_discovery      # → inspect.html
python3 scripts/td_roadmap.py     $TD_OUT_DIR/task_discovery      # → roadmap.html
python3 scripts/workshop_server.py $TD_OUT_DIR/task_discovery 8000 # http://<호스트>:8000
```

- 인자 없이 실행하면 `$TD_OUT_DIR/task_discovery`(없으면 `data/task_discovery`)를 본다.
- 출력 경로를 두 번째 인자로 줄 수 있다. **`dist/` 아래는 코드가 거부한다**(3절).
- `--anonymize`를 붙이면 실명이 `P0` 형태로 바뀌고 **회고 원문이 통째로 빠진다**.
- 생성된 HTML은 자립형이다 — 파일을 브라우저로 열기만 하면 된다(서버 불필요).

**회고 원문은 추출 입력에서 온다.** `extracted.json`에는 원문이 없다(`td_extract`가 담지
않는다). 탐색기가 같은 디렉터리의 `sources.json` 또는 그 상위의 `persons.json`을 자동으로
찾는다. 둘 다 없으면 원문 칸만 비고 나머지는 정상 동작한다.

---

## 3. 보안 — 어느 파일에 무엇이 들어가나

| 파일 | 카테고리명(L2) | 실명·인용(L3) | 회고 원문(L3) |
|---|---|---|---|
| `inspect.html` | ✅ | ✅ | ✅ **통째로** |
| `roadmap.html` | ✅ | ✅ | ❌ |
| `workshop-votes.json` | ❌ (id만) | ❌ | ❌ |

**`inspect.html`이 이 프로젝트에서 가장 민감한 산출물이다** — `workshop-input.md`는 인용
조각만 담지만 여기는 원문이 통째로 인라인된다.

- 출력은 **`$TD_OUT_DIR` 아래로만.** `dist/`는 GitHub Pages로 공개되므로
  `td_common.reject_public_path`가 그 경로를 아예 거부한다(주석으로만 두면 오타 한 번에 깨진다).
- 콘솔·예외·HTTP 400 응답에 카테고리명·실명·원문을 넣지 않는다. 건수와 인덱스만.
- 투표 파일은 **카드 id만** 담는다(`1:future_task:0` 형태). 원문이 묻어나지 않는다.

익명화 확인(합성 60명): 일반 105kb·실명 56건 노출 / `--anonymize` 85kb·**실명 0건**.

## 4. 탐색기 (`td_inspect`)

회의에서 나오는 질문 여덟 중 일곱이 **파일 하나 안에서 답이 안 나온다** — 대부분 조인
아니면 필터다. 그래서 범용 JSON 뷰어가 아니라 역추적 도구로 만들었다.

**입구가 셋이고, 셋은 같은 그래프다.**

| 탭 | 무엇 |
|---|---|
| 카테고리 | 인원순 목록 → 정의·지표·배정 항목(축별) |
| 사람 | 응답자 목록 → 그가 기여한 카테고리 전부 + 회고 원문 |
| 예외 | 무신호 / Other / 배정 폐기 |

항목의 작성자를 누르면 그 사람으로, 거기서 카테고리를 누르면 다시 카테고리로. 경로는
브레드크럼에 쌓이고 눌러서 되돌아간다.

- **전역 검색** — 서술·인용·이름·카테고리명. 매칭 부분을 표시한다. 인덱스를 만들지 않는다
  (수백~수천 건에선 매번 훑어도 체감 지연이 없다).
- **조직 필터**(pjt·cl) — 세 탭 전부에 걸린다. **걸면 카테고리의 인원·확산도·보유/갭을 남은
  카드로 다시 세고 커버리지 배지도 그 범위로 바꾼다.** 목록은 걸러졌는데 숫자가 전체면 어느
  쪽을 믿을지 알 수 없다.
- **회고 원문은 펼칠 때 DOM에 만든다.** 200명분을 미리 그리면 무겁다.

### 예외 탭 — 배정 폐기는 차집합으로

`td_assign`이 `dropped`를 반환만 하고 파일로 남기지 않아 목록이 없다. **추가 저장 없이**
`extracted`의 facet에서 `assignments`가 소비한 만큼을 뺀 차집합으로 구한다. 같은 텍스트
facet이 둘인데 하나만 배정됐으면 하나가 폐기다.

> **한계**: 추출 단계에서 **통째로 실패한 사람**은 `extracted.json`에 아예 없어 이 방법으로
> 잡히지 않는다. 커버리지의 `failed_count`도 파이프라인이 값을 넘기지 않아 항상 0이다 —
> 그 수는 추출을 돌린 실행 로그에만 있다. 화면이 이 한계를 명시한다.

## 5. 로드맵 매트릭스 (`td_roadmap`)

### 축이 두 개고 성격이 다르다

```
        준비도 ↑  (데이터가 말한 것 — 고정, 드래그 불가)
   선행신호 │  ·         ○           ◉ ← 씨앗: 지금 투자 결정
   갭만있음 │ ◉◉◉ ← 위험구역        ○
   이미함   │  ○○        ·          ·
            └─────────────────────────→ 시간 (사람이 정하는 것)
              단기        중기       장기
```

버블 크기 = 기여 인원 · 진하기 = 확산도(pjt·cl) · 선 = taxonomy relations.
**한 화면에 지표 다섯이 들어간다.** 좌상단에 몰린 덩어리가 곧 조직 리스크고, 이건 표로는
보이지 않는다.

관계선은 화면에 있는 카테고리끼리만 그린다 — 없는 곳을 가리키면 끊긴 선으로 보여 오해를 만든다.

### 카드는 두 종류뿐

투표 대상은 **`future_task`(뭘 할 것인가)**와 **`capability_gap`(뭘 언제까지 갖춰야 하는가)**.
`capability_have`·`direction`은 "언제"라는 질문 자체가 성립하지 않아 배경으로만 쓴다
(`have`는 이미 준비도 축의 계산 근거다).

### 시간축 초안 — 백지를 주지 않는다

| 카드 | 초안 위치 |
|---|---|
| 과제 | 자기 `horizon` (단기→왼쪽 / 장기→오른쪽 / 불명→가운데) |
| 역량갭 | 같은 카테고리에서 **가장 이른 과제보다 한 칸 왼쪽** |
| 과제가 없는 카테고리의 역량갭 | 가운데 (당길 기준이 없다) |

참석자는 **이견 있는 것만** 옮긴다. 사람은 백지보다 초안 수정을 훨씬 잘한다.

### 선후 제약

**역량은 그걸 쓰는 과제보다 먼저 확보돼야 한다.** 역량갭이 같은 카테고리에서 가장 이른
과제보다 뒤에 있으면 위반으로 표시한다 — 그 과제를 시작할 때 역량이 아직 없다는 뜻이다.

차단이 아니라 **경고**다. 의도적으로 그렇게 둘 수 있고 그 자체가 논의거리다.
같은 밴드는 위반이 아니고, 한 종류만 있는 카테고리는 판정할 근거가 없어 건너뛴다.

> 초안과 판정이 **같은 기준**(가장 이른 과제)을 쓴다. 초안이 스스로 경고를 만들면 경고가
> 무의미해진다.

### 카드 배치 모드 (A단계 — 서버 없이)

카테고리를 골라 카드를 3열에 깔고 드래그한다. **서술을 크게, 원문 인용은 접어서** — 발췌만
으로는 무슨 과제인지 모를 수 있다. 옮긴 카드는 테두리와 `초안 단기 → 장기` 표시가 붙는다.

**매트릭스는 입력이 아니라 산출이다.** 카테고리 위치를 직접 찍지 않고 카드 배치를 집계해서
얻는다 — 카드를 옮기면 버블이 즉시 따라 움직이고 선후 위반도 다시 계산된다.

내보내기(JSON)는 **초안과 확정을 둘 다** 남긴다. 무엇을 바꿨는지가 없으면 나중에 그 결정을
방어할 수 없다 — 워크숍 산출물의 절반이 "우리가 데이터를 어디서 뒤집었나"다.

> **로컬 저장이 없다.** 새로고침하면 배치가 날아간다. 내보내기 버튼이 저장 수단이고,
> 서버(6절)를 띄우면 해결된다.

## 6. 투표 서버 (`workshop_server`)

엔드포인트 셋뿐 — `GET /state` · `POST /vote` · 정적 페이지. 화면은 5절 그대로이고
**상태 소스만 폴링(3초)으로 바뀐다.**

### 집계 규칙

| 상황 | 결과 |
|---|---|
| 최빈값 단독 1위 | 그 구간으로 확정 |
| **동률** | **초안 유지** — 사람이 정하지 못한 것을 임의로 밀지 않는다 |
| **최빈값이 과반(절반 초과) 미달** | 확정은 하되 **이견 카드**로 분류 |
| 표 없음 | 초안 유지. 아무도 안 본 것이지 갈린 게 아니다 |

**사람당 한 표.** 같은 사람이 다시 투표하면 앞의 표를 바꾼다 — 논의 중에 생각이 바뀌는 게
이 워크숍의 목적이다.

### 이견 아젠다가 이 서버의 존재 이유다

카드가 수백 장이다. **갈린 카드만 뽑으면 논의할 스무 장으로 줄어든다.** 합의된 것은 자동
통과, 갈린 것만 사람 시간을 쓴다. 이 장치가 없으면 그 규모는 물리적으로 소화 불가능하다.

800장 대응은 세 겹이다: **조직 필터** → **초안 + 이견만 이동** → **갈린 것만 논의**.

### 하지 않는 것과 그 이유

| | |
|---|---|
| DB 없음 | 몇 시간짜리 1회성 세션, 참석자 수십 명. 투표마다 JSON write-through 하면 서버가 죽어도 재시작 시 복구된다. 이 저장소의 기존 철학(파일 영속화)과 같다 |
| 새 의존성 없음 | 엔드포인트가 셋뿐이라 stdlib `ThreadingHTTPServer`로 충분 |
| WebSocket 없음 | 갱신 빈도가 낮아 폴링으로 충분하고 재연결 처리가 필요 없다 |
| 인증 없음 | 사내 폐쇄망에서 진행자가 URL을 공유하는 방식 |

**서버가 붙으면 서버 계산이 정본이다.** 브라우저에도 같은 규칙의 사본이 있지만 정적 모드
(서버 없이 파일만 열기)에서만 쓰인다 — 같은 규칙을 두 곳에서 동시에 돌리면 언젠가 갈라진다.
파이썬 쪽이 정본이고 테스트가 그쪽을 고정한다.

## 7. 카드 id — 왜 `text`를 쓰면 안 되나

**투표 키를 카드 `text`로 두면 한 표가 여러 카드에 먹힌다.** 합성 데이터 60명에서만 서로
다른 사람이 같은 문장을 쓴 카드가 **31개 그룹** 있었고, 실제로 2장에 투표했는데 33장이
투표된 것으로 잡혔다.

id는 **`(사람 id):(축):(그 안에서 몇 번째)`** — 예: `12:future_task:0`.

- 위치 기반이라 `extracted`/`assignments`가 그대로면 **재생성해도 같은 값**이 나온다
  (`td_assign`의 재개 판정과 같은 근거). 이전 세션의 표가 살아난다.
- **원문을 넣지 않는다** — id는 로그·URL에 실릴 수 있다.

## 8. 알려진 한계

| | 무엇 | 영향 |
|---|---|---|
| 1 | **`have=0·gap=0`인 카테고리가 "이미 함"으로 잡힌다** | `td_aggregate`의 판정식이 그렇게 떨어진다. 실제로는 "역량 언급이 없다"이지 "보유가 우세하다"가 아니다. **매트릭스 세로축이 이 값을 쓴다** — 고쳐 쓰지 않고 `capability_silent`로 사실만 표시한다(Layer 1의 의미를 바꾸는 건 별도 판단) |
| 2 | 추출 통째 실패 인원은 어느 목록에도 없다 | 4절 참고. 실행 로그에만 |
| 3 | 배치가 새로고침에 날아간다 (A단계) | 내보내기가 저장 수단. 서버를 띄우면 해결 |
| 4 | `workshop-votes.json`을 그 다음에 무엇이 소비하는지 미정 | 산출물이 1회성인지 반복인지가 안 정해졌다 |

---

## 9. 미결로 남은 것

- **산출물이 1회성인가 반복 산출인가** — 이게 정해져야 투표 결과의 소비처가 정해진다.
- **`td_aggregate` 준비도 판정**을 고칠지(위 8-1).
- 실명 표기 정책 — 지금은 **실명이 기본**이고 `--anonymize`로 끌 수 있다.
- 출력용(PDF·슬라이드) — v1은 JSON 내보내기만. 워크숍 포맷이 확정된 뒤.

## 10. 검증 상태

- 테스트 **261개** 통과. 카드 조인 19 · 탐색기 14 · 로드맵 26 · 서버 19 + 기존.
- 전부 **합성 데이터 + 인메모리 주입**. 네트워크·파일시스템 의존 없음(HTTP는 스모크 4개).
- 헤드리스 크롬으로 실제 화면 확인: 탭 전환·왕복·브레드크럼·검색·필터·예외 3갈래·
  드래그 배치·집계 반영·원문 지연 렌더.
- 투표 서버 종단 확인: 갈린 표→이견 / 같은 표→합의 / 마음 바꾸기 / **재시작 복구**.
- **실데이터로는 한 번도 돌리지 않았다** — 사내망 몫이다.
