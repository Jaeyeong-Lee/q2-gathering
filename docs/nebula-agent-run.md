# Claude Code가 모델 자리에 들어가서 돌리기

내부 GPT-OSS endpoint를 부르는 대신, **이 실행을 몰고 있는 에이전트가 각 단계의 답을 직접 쓴다.**
프롬프트를 손으로 시험해 보거나, endpoint 없이 합성 코퍼스로 끝까지 돌려볼 때 쓴다.

설계는 [[nebula-spec]], 운영 전반은 [[nebula-internal-runbook]], 이 패키지에서 지켜야 할 것은
`nebula/CLAUDE.md`에 있다. 이 문서는 **에이전트가 도는 루프 하나**만 다룬다.

## 먼저 — 어떤 자료에 쓸 수 있나

이 방식은 원문이 **에이전트의 컨텍스트로 들어온다**. 루트 `CLAUDE.md`가 금지하는 바로 그 일이다.

- **합성 코퍼스: 써도 된다.** `python -m nebula demo`가 만드는 입력, `data/td_sample/`.
- **실데이터: 쓰지 않는다.** 사람의 회고 원문을 `--agent`로 처리하는 것은 네트워크 밖으로
  원문을 내보내는 것과 같다. 그 규칙을 바꾸는 것은 코드가 아니라 사람이 결정할 일이다.
  실데이터는 내부망 endpoint(`NEBULA_BASE_URL`)로 돌린다.

판단이 서지 않으면 멈추고 물어본다. 이 문서는 허가가 아니다.

## 루프

```
python -m nebula run --input <입력.json> --out <OUT> --agent
```

종료 코드 **2**는 실패가 아니라 **차례가 넘어왔다는 뜻**이다. stderr에 답을 쓸 경로가 찍힌다:

```
agent turn: answer tasks at <OUT>/agent-requests/tasks/<key>.answer.json
```

1. 그 경로에서 `.answer.json`을 뗀 파일이 **요청**이다. 열면 세 가지가 들어 있다.
   - `stage` — 지금 단계 (`tasks`, `capabilities`, `links`, `taxonomy`, `consolidate`, `assign`)
   - `instructions` — 그 단계의 프롬프트. **그대로 따른다.** 요약하거나 고쳐 읽지 않는다.
   - `input` — 그 단계가 보는 입력 전부
2. `instructions`가 요구하는 JSON 객체 **하나**를 `answer_path`에 쓴다. 다른 건 쓰지 않는다 —
   설명도, 마크다운 코드펜스도, 주석도 넣지 않는다.
3. **같은 명령을 다시 실행한다.** 답이 검증을 통과하면 `cache/`로 옮겨지고 다음 단계로 넘어간다.
4. 종료 코드 0이 나올 때까지 반복한다. 그때 `status.json`이 `complete`가 되고 HTML 세 개가 나온다.

경로는 **stderr에 찍힌 것을 쓴다.** 입력이 바뀌면 답을 못 받은 옛 요청 파일이 남을 수 있어서,
디렉터리를 뒤져 고르면 엉뚱한 단계에 답하게 된다.

## 답을 쓸 때

- **인용은 원문에서 글자 그대로 복사한다.** 공백·개행까지 같아야 하고, 다듬거나 줄이면 거부된다.
  `occurrence`는 그 인용이 원문에서 몇 번째로 나오는지다(1부터).
- **없는 것을 만들지 않는다.** 근거가 없으면 그 항목은 빼고, 빈 배열이 정답인 경우가 많다.
- **모르는 것은 모른다고 둔다.** 시점이 원문에 없으면 `horizon`은 `"unknown"`,
  `time_quote`는 `null`이다. 그럴듯하게 채우면 그 값이 그대로 발표 화면에 올라간다.
- `ref`는 파이프라인이 붙인다. `links` 단계에서는 입력에 주어진 `ref`를 그대로 쓴다.
- 답이 틀리면 **거부되고 캐시에 들어가지 않는다.** 오류 메시지를 읽고 같은 파일을 고쳐 쓰면 된다.
  통과시키려고 검증을 고치는 것은 언제나 틀린 수정이다.

## 중간에 멈췄을 때

- `status.json`의 `stage`와 `call_key`가 어디서 멈췄는지 말해 준다.
- 같은 `--out`으로 다시 실행하면 이미 통과한 단계는 캐시에서 재사용한다. 처음부터 다시 하지 않는다.
- 모델로 갈아타려면 `--agent` 없이 같은 명령을 돌린다. 캐시 키에 provider가 들어가므로
  에이전트가 답한 단계와 모델이 답한 단계는 섞이지 않는다 — 새 provider로는 전부 다시 묻는다.
- 한 사람의 추출만 고치고 싶으면 `--agent`보다 `corrections-template.json` 쪽이 맞다.
  runbook의 검토·수정 절에 있다.
