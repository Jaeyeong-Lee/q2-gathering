## 3. 방법론 인사이트 — 에이전트×모델 조합의 교훈

### 3.1 완성도는 모델보다 "에이전트 루프 안정성"이 좌우한다

- **Claude Code CLI (Sonnet, qwen)**: 루프가 안정적. Sonnet은 보고까지 완벽, qwen도 CC에선 끝까지 갔다 —
  같은 qwen이 codex exec에서는 **3번 연속 탐색 중 스스로 Stop**했다. CC의 루프 설계가 약한 모델을 끌고 간다.
- **Codex exec + OpenRouter**: gpt-6-astra·kimi·minimax는 잘 갔지만, **중간에 402(크레딧)로 끊길 확률이 높다.**
  끊긴 세션을 "이전 상태 요약 + 남은 것만" 컨텍스트로 재시작하면 마무리는 가능했다 (kimi, minimax 모두 성공).

### 3.2 동시 병렬 실행의 숨은 비용

- OpenRouter는 **in-flight 요청들의 예상 비용 합계**로 크레딧을 잠근다. 3개 동시에 큰 컨텍스트로 돌리면
  잔액이 충분해도 402. **동시 실행 시 잔액 ≥ 1회 예상치 × 동시수** 필수.
- 실험 규모가 커질수록 "동시 N개"보다 "순차 2개 + 저가 모델 우선"이 실질적으로 빠르다.

### 3.3 가성비의 냉정한 계산

- **fable 5.1 사건**: 1.12M 토큰 ≈ **$11+ 소진, 산출물 0.** 전체 실험비의 60%를 한 실패가 썼다.
  고가 모델은 "탐색이 길고 실패하면 손해가 극대화"된다 — 브리프 이해도가 확신 없으면 저가로 파일럿 먼저.
- **qwen-coder-flash ($0.20/$0.97)**: 코드 품질은 합격(38/38 테스트)이지만 지시 이탈(카드 덱→무대 베끼기)과
  마무리 누락(스크린샷 미생성)이 반복됐다. **싸지만 감독 비용이 든다.** 단순 조판·구현엔 최적, 설계 재량엔 부적합.
- **minimax-m3 ($0.30/$1.00)**: 420k 토큰 ≈ **$0.6 수준**. agentic 특화답게 재시작 후 문맥 이어받기가 좋았으나
  `apply_patch` 툴 미지원 → sed 우회. 툴 스키마 호환성은 모델마다 다르다.
- **kimi-k3**: 비싸지만($2.65/$13.28, 179k ≈ $1.2) **결과물 품질·자발적 제안(deck 용어 통일)이 가장 좋았다**.
  "비싼 모델은 재작업이 적다"는 공식이 여기선 성립.

### 3.4 시간 — 완료까지의 실측

| 후보 | 세션 수 | 대략 소요 | 특기사항 |
|---|---|---|---|
| codex | 1 | ~15분 | 최초 착신 |
| claude | 1 | ~30분 | CC 루프 안정 |
| kimi | 2 | ~50분 | 402 끊김 + 마무리 세션 |
| qwen | 4 | ~90분 | codex 3회 실패 → CC 전환 → 샷 캡처까지 총 4단계 |
| minimax | 3 | ~70분 | 402 + apply_patch + README 누락 → 오케스트레이터 마무리 |

**"빠른 모델"보다 "루프를 안 빠지는 모델"이 실제로 빠르다.** qwen은 토큰당 가장 싸지만 세션 4번 돌려
결국 오케스트레이터가 스크린샷을 찍어줘야 했다.

### 3.5 오케스트레이터(헤르메스)의 역할이 커졌다

이번 실험에서 실제로 일한 것:

- 배포·커밋 누락 수습 (minimax README, qwen 스크린샷, story-claude 좀비 세션 수습)

- 검수 재실행 및 story 회귀 확인

즉 **"모델을 고르는 것"보다 "모델이 흘러가지 않게 잡아주는 것"이 오케스트레이션의 실무 가치**였다.

어차피 최종은 "다 짬뽕해서 베스트 하나"다. 후보별로 **가져올 것**:

| 소스 후보 | 통합안에 가져올 요소 |
|---|---|
| claude (무대와 무인) | **하단 자막 밴드** (장면 문장이 자막처럼 등장·소멸 — 발표 리듬 장치) + **현장 카드** (근거를 지도 위 직접 표시) + 암전 큐 전환 |
| codex (관측 궤도) | **장면별 카메라 변주** — 장면 0 저앵글, 클로즈업 궤도 회전, 격자 탑뷰. 단, 조작 중 변주는 완만하게 |

| minimax (관제탑) | **상단 시간축 레일 상시 노출** — "10년 로드맵" 요구에 대한 정직성 장치. 하단 상태줄(선택 대상 실시간 표기) |

**비축 요소 (버릴 것)**

- fable "초월적 여백": 흥미로운 발상이었으나 70% 비움은 데모 조작과 상충 — 소량의 여백은 유용하나 전체 구도론은 버림
- 1부 성운 리뷰 때의 "글자 전부 크게" — 2부 라이브 데모는 **조작 가능한 크기**를 유지 (본문 16~18px 선)

### 예상 개선점 (다음 라운드를 위한 남은 것)

1. **통합 계약 결정** — "무대와 무인"의 하단 밴드 + "관제탑"의 시간 레일이 서로 하단을 두려는 충돌. 해결안:
   자막 밴드(claude)를 시간축 레일(minimax) 위에 겹치는 **이중 하단** — 자막이 뜰 때만 레일이 흐려진다
2. **카메라 이동 + 클릭 좌표** — codex의 궤도 구도는 클릭 후 카메라 복귀 애니메이션이 필요 (claude의 `cue()` 방식 참고)
3. **폰트 임베딩** — Pretendard 웹폰트 CDN은 발표장 네트워크 단절 시 무용지물. **페이퍼로지(660KB) 로컬 임베딩**을
   PPT/HTML 어느 쪽에도 넣을 수 있게 하는 것이 발표 전 마지막 과제
4. **라이브 데모 프레임 개선** — 전환 프레임 11→7개(claude 기준)도 50ms 넘는 프레임이 7개나 남아 있다.
   320명 픽스처 기준 성능 목표: 50ms 프레임 3개 이하
5. **1부/2부 톤 일관성** — 1부(story, 합성)와 2부(live, 실데이터)가 같은 엔진을 쓰는데 통합 후 배경 밀도가
   달라지지 않는지 재확인 필요
