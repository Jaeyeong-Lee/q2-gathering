# 미래 과제 발굴 (task-discovery) 설계

2026-07-16 그릴링 세션에서 Jay와 합의한 설계. 브랜치: `feat/task-discovery`.
2026-07-17 이슈 #1(스펙)~#7 전부 구현·커밋됨 — 더미 20명 데모 실물이 `dist/wiki/`에 있음.
2026-07-18 그릴링(요약층·시각화·추출 충실화)이 아래 "확장 설계" 섹션에 추가됨.

## 목표

근원경쟁력 회고(238명, pptx 텍스트)에서 ① 팀원들이 직접 쓴 미래 과제를 군집화해
"미래 과제 지도"로 정리하고, ② 역량×과제 대조로 아무도 안 쓴 새 과제를 발굴하는
**wiki** (군집당 md 페이지, GitHub Pages 정적 서빙).

원문 템플릿: CL2/3는 3단 구성(①상반기 성과·하반기 전략 ②커리어 회고·확보 역량
③단기/장기 미래 업무), CL4는 미래 위주로 템플릿이 아예 다름. 일부 미준수자 존재 — 감수.

## 파이프라인 (전부 빌드타임, 런타임 API zero 유지)

```
pptx 원문 텍스트 (238명)
  → [LLM 추출: 인당 1회, CL별 프롬프트 분리]
     {tasks[]: text·horizon(단기/장기/불명)·원문 인용,
      capabilities[]: text·인용} + 작성자 id
  → [과제 문장별 임베딩]  ← 사람당 1개 아님. 238명 × 3~5과제 ≈ 700~1,000 벡터
  → [군집화: 과제 평면 + 역량 평면 각각]  ← KMeans (정규화 후 유클리드 = 코사인,
                                            k-means++ 초기화, sklearn 사용 OK)
  → [군집당 LLM 1회: 페이지 생성] → 군집당 md 파일 = wiki 페이지
  → [발굴: wiki 과제 페이지 풍부화]  ← 군집별 파생 과제 제안 등. 인용 원칙 동일
  → [옵션: 빈 칸 매트릭스: 역량군집 × 과제군집 중심벡터 코사인]
     → 어떤 과제 군집과도 안 붙는 역량 군집 = 발굴 포인트
     → 그 빈 칸에만 LLM 생성 과제. 근거 인원 id 인용 필수 — 인용 못 하면 폐기
     → (2026-07-17) 필수 → 옵션으로 강등: 발굴의 1차 경로는 페이지 풍부화,
       매트릭스는 그 뒤의 확장
```

## 결정과 기각 (왜 이렇게 생겼는지)

- **RAG 아님** (기존 결정 유지): lookup은 발굴 질문("전체를 조망해 빈 곳 찾기")에
  검색어를 만들 수 없다. 사내 RAG는 발굴 결과의 세부 확인용 보조.
- **사람 단위 군집 기각 → 과제 문장 단위**: 목표가 과제 지도인데 원문 3단 템플릿에
  과제가 이미 데이터로 존재한다. LLM이 과제를 창작(합성)하는 게 아니라 팀원이 쓴
  과제를 집계 — "AI가 지어낸 과제"와 "팀원 N명이 실제로 쓴 과제"는 설득력이 다르다.
  한 사람이 여러 군집에 등장 가능. 작성자 trace는 문장 단위로 유지.
- **"요약" 아님, "항목화"**: 미래 위주 요약 → 사람당 재임베딩은 다시 사람 단위
  지도가 된다(기각 방향으로 회귀). 추출은 JSON 리스트로 정보를 쪼갠다.
- **Karpathy식 순차 wiki iteration 기각 → 배치 파이프라인**: 순차 갱신은 초반
  문서들이 만든 페이지 구조에 나머지가 끼워 맞춰지고(순서 의존), 프롬프트 수정마다
  238회 순차 재실행. 배치는 추출·임베딩이 캐시돼 군집 수/페이지 프롬프트만 바꿔
  재생성. 데이터가 반기 1회라 증분 갱신 불필요 — 다음 반기에 전체 재생성이 정답.
  wiki라는 산출물 형태만 가져오고 엔진은 임베딩.
- **생성층(LLM 상상력)은 구조화된 재조합만**: 자유 브레인스토밍은 근거 없는
  그럴듯한 과제 생성기가 된다. 빈 칸 찾기부터(기계적으로 정의돼 검증 가능).
  군집 쌍 교차 조합("A 역량으로 B 과제를 하면?")·외부 트렌드 주입은 빈 칸이
  돌아간 뒤의 확장.
- **실명 + 원문 인용 (과제 페이지)**: 미래 업무는 본인이 회사에 제출한 희망사항이라
  인용 부담이 낮고, 팀장에게 "과제 → 하고 싶다는 사람"으로 바로 이어지는 게 이
  wiki의 존재 이유. 사내 한정 서빙.
- **단기/장기는 태그·배지만, 군집은 통합**: 같은 주제를 단기로 쓴 사람과 장기로
  쓴 사람은 같은 방향의 동지 — 지평선으로 군집을 쪼개면 주제 지도가 반토막.
  추출 필드 하나 추가라 비용 0, 미준수 문서는 `불명`.
- **인터랙티브 뷰(기존 archive 스타일) 보류**: md 보고서/wiki로 시작. 군집당
  파일 하나 구조면 wiki가 공짜로 따라온다. 팀장이 인터랙티브를 원하는 신호가
  오기 전까지 짓지 않는다.

## 마일스톤

## 확장 설계 (2026-07-18 그릴링 합의 — 이슈 #8~#10으로 구현·커밋 완료)

구현 상세 해설(스키마·생각의 경로·리뷰 반영·함정)은 `docs/task-discovery-implementation.md`.

문제의식: 파이프라인이 "모으기"까지만 하고 의미 찾기·정제가 없다. 위키 나열만으로는
보여주는 의미가 약하다. 세 갈래로 확장한다.

### 1. 요약층 — 위키 index 상단 총평

- 파이프라인 끝에 **LLM 1콜 추가**: 전 군집의 제목·요지·규모·문장을 입력으로
  ① **큰 흐름 2~3개** 서술("팀 전체가 어디로 수렴 중인가")
  ② **소수 의견·특이점** — 한두 명만 쓴 독특한 과제, 군집에 잘 안 붙는 외톨이 문장 조명.
- index.md 맨 위 "총평" 섹션으로. 인용 원칙 동일(근거 문장 대조 가능해야 함).
- **우선순위 제안은 보류** — "인원수·단기 비중·역량 근접도(과제×역량 군집 중심벡터
  코사인) 지표 3개만 표로 노출, 순위는 매기지 않음(가중치 근거 시비 방지)" 제안까지
  나왔고 Jay 결정 대기. 메모리에 기록됨. 이번 스코프에 넣지 않는다.

### 2. 시각화 — 과제 문장 그래프 (기존 아카이브 통합)

- **노드 = 과제 문장**, 색 = 군집. 클릭 → 인용 카드(실명·CL·horizon·원문 인용) +
  해당 군집 위키 페이지 링크. 위키(글로 읽는 지도)와 그래프(눈으로 보는 같은 지도)는
  같은 군집 결과의 출구 두 개.
- **기존 heritage-archive.html에 통합** (별도 파일 아님 — Jay 결정): 헤더 토글
  [사람 지도|과제 지도] + `#view=tasks` 딥링크(기존 `#view=` 패턴 재사용).
- **두 지도는 상태 미공유** — 사람 지도의 팀/CL 필터가 과제 지도에 이월되지 않는다.
  "필터 경로가 두 개면 헷갈린다" 교훈 유지. 탈출구: 통합으로 템플릿 IIFE가 심하게
  복잡해지면 별도 파일로 후퇴한다.
- **엣지 = 과제 벡터 유사도 top-K** (`similarity.py` 재사용, 사람 지도와 동일 문법).
  군집이 물리적으로 뭉치고 군집 간 인접 관계도 배치에서 드러난다.
- **외톨이 노드**(군집 중심에서 먼 문장 = 소수 의견) 시각 구분 표시 — 텍스트 총평의
  소수 의견 항목과 짝을 이룬다.
- 사람 유사도 지도와의 **카드 수준 연계**(과제 카드 이름 클릭 → `#ego=<id>`, 사람
  카드에 미래 과제 목록)는 **실데이터 이후로 보류** — 지금은 두 더미 인구(아카이브
  150명 vs task 20명)가 서로 달라 이어질 사람이 없다. 실데이터에선 id 정합만 맞추면
  기존 딥링크 재사용으로 공짜에 가깝다.

### 3. 추출 충실화 — verbose 원문 대응 (실데이터 직전 스코프)

현재 추출은 항목당 **짧은 문장으로 압축**한다(text 한 줄 + quote 한 조각). 더미
원문이 한 줄짜리라 티가 안 났지만, 실 pptx는 과제 하나를 반 페이지씩 verbose하게
서술하므로 구체성이 추출에서 소실된다. "요약 아님, 항목화" 원칙이 금지한 것은
사람 단위 압축이지 항목 내부 압축이 아니었음 — 항목 내부도 충실해야 한다.

- **text**: 짧은 라벨 → **원문의 구체성(대상 공정·방법·이유)을 보존한 충실한 서술**
  (여러 문장 허용). 임베딩 입력이 이것이므로 군집 정확도의 핵심. 구체성이 뭉개지면
  군집이 죽처럼 붙는다.
- **quote → quotes[] 복수화**: verbose 원문에선 한 과제 얘기가 흩어져 있어 연속 발췌
  하나로 못 담는다. 각 인용을 개별 원문 대조(공백 정규화 비교 유지).
- **더미 생성기 업그레이드**: 한 줄 과제 → verbose 서술형 더미(문단 단위, 흩어진
  언급 포함)로. 이게 없으면 위 두 변경을 검증할 수 없다.
- 시점: **실데이터 직전** — verbose 더미와 함께 진행. 지금 한 줄 더미로는 검증 불가.

### 구현 순서 (제안)

1. 추출 충실화 + verbose 더미 (3) → 재실행으로 군집 품질 확인
2. 요약층 총평 (1) — 파이프라인 1콜 추가
3. 과제 그래프 뷰 (2) — 아카이브 통합, 가장 큰 작업
이슈 분해는 to-issues로. 보류 항목(우선순위 지표, 사람 지도 연계)은 이슈에 넣지 않는다.
