# 오프닝 — 원자료가 스스로 정돈되는 장면 (컨셉 메모, 미착수)

> 상태: **컨셉만 있음. 티켓 없음, 코드 없음.** 다음에 착수하려면 이 문서 하단의
> "티켓화 전에 정할 것"을 먼저 답해야 한다.

## 요구사항 원문

PPT 수백 개가 쌓이는 이펙트로 시작해서, 그게 유사도 변환·추출·택소노미로 이어지는
발표덱. 텍스트 설명보다 그림을 크게.

**갱신**: 사실적 PPT 썸네일이 아니라 **각 절차를 아이콘 하나로 크게** 표현하고,
그 절차(쌓임→유사도→추출→택소노미) 전체를 아이콘 전환 이펙트로 보여준다.

## 붙는 위치

지금 만들고 있는 `nebula/templates/nebula.html` 다섯 장면(사람→과제→성운→시간→역량)
**앞에 붙는 프리롤(scene −1)**로 제안. 청중이 "이거 진짜 원문에서 나온 거 맞아?"를
묻기 전에 원자료 → 파이프라인 → 정돈된 결과의 전체 그림을 30초 안에 먼저 보여주는 용도.

독립 덱(파이프라인 설명 전용)으로 뗄 수도 있으나, 그러면 이 SVG 애니메이션 인프라를
그대로 못 쓰고 새로 짜야 한다 — 아래 실현성 평가 참고.

## 비트 구성 (4단계, 컷 전환 아님 — 하나가 다른 것으로 계속 변형됨)

1. **쌓임 (Raw)** — PPT 썸네일 수백 개가 위에서 쏟아져 무질서하게 쌓인다. 텍스트는
   흐릿하게(합성이든 실제든 판독 불가 처리) — "많다"만 전달. 마지막 한 장이 떨어지는
   순간 전체가 살짝 진동.
   - 카피 후보: `200장. 아무도 두 번 안 읽은 글.`
2. **유사도 (Similarity)** — 더미가 순간적으로 점(dot) 구름으로 붕괴, PPT 한 장 = 점
   하나. 점들이 서로 끌리고 밀리며 재배치 — 비슷한 사람은 가까이, 먼 사람은 멀리.
   이 움직임 자체가 "유사도"를 설명, 라벨 최소화.
3. **추출 (Extraction)** — 클러스터를 확대하면 점 하나가 원문 문장으로 펼쳐짐, 실제
   인용 카드가 튀어나오는 연출. 처음으로 "읽을 수 있는" 텍스트 등장 — 1단계의 흐림과
   대비. "원문을 지어내지 않았다"는 신뢰 메시지를 시각으로 증명.
4. **택소노미 (Taxonomy)** — 흩어진 카드들이 다시 모이며 라벨 달린 그룹으로 정착.
   1단계와 정확히 같은 화면 비율/카메라 앵글로 마무리 — "같은 자료다, 정리만 됐다".

## 톤 원칙

- 텍스트 최소, 이미지 최대. 각 장면 카피 1줄 이하 — 전환 자체가 설명.
- 여백 없이 화면 꽉 채움. 작은 다이어그램 여러 개보다 큰 그림 하나.
- 색상은 무채색 더미 → 3단계부터 PJT별 색 등장(기존 `nebula.html`의 8색 팔레트
  재사용). "정리되기 전엔 색이 없다"는 은유.

## 아이콘 기반 연출 (사실적 썸네일 대신)

4단계 전부를 "화면을 채우는 큰 아이콘 하나 + 그 아이콘이 다음 아이콘으로 넘어가는
이펙트"로 통일한다. 사진 같은 PPT 목업을 만드는 대신 픽토그램을 쓰면, 개별 문서의
디테일에 눈이 쏠리지 않고 "이 단계가 무엇을 하는가"만 남는다 — 나레이션 없는
오프닝의 목적과도 맞는다.

1. **쌓임** — 문서 아이콘(모서리 접힌 사각형) 한 장이 화면 중앙에 크게 나타나고,
   같은 아이콘이 뒤로 겹겹이 쌓이며 화면을 채운다. 개수를 셀 수 없을 만큼 빽빽해지는
   것 자체가 "수백 개"의 인상.
2. **유사도** — 쌓인 문서 더미 아이콘이 점(dot)들이 흩뿌려진 네트워크 아이콘으로
   전환. 점들이 선으로 이어지며 몇 개 군집으로 뭉친다 — "묶는다"는 동작을 아이콘
   레벨에서 그대로 보여줌.
3. **추출** — 깔때기/집게 아이콘이 군집에서 문장 조각(따옴표 아이콘)을 하나씩
   뽑아내는 모션. 여기서 처음으로 텍스트 파편(합성 문구)이 등장해 "실제로 뭔가
   나온다"는 것을 보여준다.
4. **택소노미** — 뽑힌 조각들이 라벨 붙은 폴더/상자 아이콘으로 정착. 상자 몇 개가
   화면에 정렬되며 마무리 — 1단계의 무질서한 더미와 대구를 이루는 정돈된 그리드.

아이콘 스타일은 `nebula.html`의 기존 톤(얇은 선, `--violet`/`--mint`/`--rose` 팔레트,
장식 없는 선 굵기)을 그대로 따른다 — 새 비주얼 언어를 만들지 않는다.

## 실현성 평가

가능하다고 본다 — 아이콘 기반으로 정하면서 오히려 리스크가 줄었다. 사실적 PPT
목업은 만들수록 어설퍼 보이는 함정이 있는데, 선 아이콘은 SVG `<path>` 몇 개로
끝나고 `nebula.html`이 이미 쓰는 스타일과 자연히 어울린다. 근거는 코드를 실제로
열어서 확인한 것:

- `nebula.html`은 이미 "장면(scene) → 좌표 계산(`target(t)`) → CSS transition으로
  자동 보간"이라는 엔진을 갖고 있다. 각 별의 `.style.transform`을 바꾸기만 하면
  `transition:transform 1.65s cubic-bezier(.22,.75,.18,1)`가 알아서 이동을 그려준다.
  즉 프리롤은 **새 렌더링 방식이 아니라 이 엔진에 `scene -1`을 하나 추가**하는 문제다.
  - 1단계(쌓임 아이콘): 문서 아이콘 하나를 `<path>`로 정의해 두고, 같은 심볼을
    `<use>`로 반복 배치하며 개수를 늘려간다 — 별개 shape을 새로 그릴 필요 없이
    아이콘 1종만 만들면 된다.
  - 2단계(유사도 아이콘): 문서 아이콘 그룹과 네트워크 아이콘(점+선) 그룹을
    fade-out/fade-in으로 교차, 점 좌표는 미리 계산해 겹쳐 놓는다. 아이콘 간
    shape morph는 시도하지 않는다 — 크로스페이드로 충분하고 훨씬 안전하다.
  - 3단계(추출 아이콘): 기존 `.evidence` 카드 스타일(`review.html`에 이미 있음)을
    확대해서 재사용. 깔때기/집게 아이콘도 `<path>` 하나.
  - 4단계(택소노미 아이콘): 기존 성운 라벨(`nebula-label`) 렌더 함수를 그대로 쓴다.
- 실데이터 없이도(합성 200명) 이 프리롤을 통째로 만들고 검증할 수 있다 — 아이콘은
  합성이든 실제든 상관없이 항상 같은 그림이라 원본 자료와 무관하다.
- 리스크는 아이콘 4종의 디자인 완성도지 기술 난이도가 아니다. SVG 아이콘은
  간단할수록 좋다 — 디테일을 더 넣으려는 유혹을 피한다.

## 티켓화 전에 정할 것

- **적용 대상**: `nebula.html` 프리롤로 붙일지, 완전히 별도 파일로 뗄지.
- **길이**: 자동재생 시 몇 초를 쓸지 (기존 다섯 장면은 수동 진행 + 자동 발표 옵션 둘 다
  있음 — 프리롤도 스킵 가능해야 하는지).
  - 스킵 불가면 매번 보는 사람이 답답해할 수 있음 — 최초 1회만 재생하고 이후 스킵하는
    로직이 필요한지도 결정 필요.
- ~~1단계 PPT 썸네일 사실도~~ — **결정됨: 아이콘 기반**. 사실적 목업 안 만든다.
- **입력 데이터**: 이 프리롤이 실제 인물 수(200명)를 반영해야 하는지, 아니면 "수백 개"
  라는 인상만 주면 되는(개수 고정된 연출용 더미) 것인지 — 전자면 `D.people.length`를
  읽어야 하고 후자면 하드코딩 가능.
- **아이콘 출처**: 4종 아이콘(문서·네트워크·추출·분류함)을 직접 그린 `<path>`로
  만들지, 기존 아이콘 세트에서 골라 스타일만 맞출지.

이 셋에 답이 서면 `todos/`나 gh 이슈로 옮겨서 착수할 수 있다.
