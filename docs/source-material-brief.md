# 근원경쟁력 자료 — 원재료 브리프

> **받는 쪽:** 이 저장소도, 실데이터도 못 보는 다른 모델.
> **부탁하는 것:** "이 텍스트 뭉치에서 무엇을 읽어낼 수 있나"를 상상하는 것.
>
> **이 문서에는 해법이 없다.** 이미 만들어둔 파이프라인이 있지만 그 개념·용어·구조를
> 일부러 뺐다 — 먼저 읽으면 거기에 갇힌다. 원재료와 상황만 놓는다.
>
> **실데이터는 한 줄도 없다.** 아래 예시 텍스트는 전부 합성이다. 실제 이름·실제 회고는
> 사내망 밖으로 나갈 수 없고, 이 문서를 읽는 쪽도 원문을 볼 일이 없다.
>
> 작성 2026-09-09.

---

## 1. 자료가 뭐냐

반도체 **후공정(back-end) DRAM 테스트** 부서의 구성원 약 200명이,
**"근원경쟁력"**이라는 제목으로 각자 쓴 회고 한 편씩.

한 사람이 PPT 슬라이드 3~6장 분량을 썼고, 그걸 파싱해 **1인 1텍스트**(대략 300~1,200자,
한국어)로 만들어 둔 상태다. 지금 손에 있는 건 그 텍스트 200편과, 각 편에 붙은
이름·직급대·소속 세 줄이 전부다.

**1회성 수집이다.** 분기마다 도는 게 아니고, 작년치도 없다. 시계열이 아니라 스냅샷 하나.

---

## 2. 누가, 어떤 상황에서 썼나 — 텍스트의 성질을 결정하는 조건

읽어내려는 게 텍스트라면, 그게 어떻게 쓰였는지가 데이터의 절반이다.

- **회사가 시켜서 썼다.** 자발적 기록이 아니라 지시받은 제출물이다.
- **상사가 읽는다는 걸 알고 썼다.** 인사평가와 직접 연결되진 않지만, 읽는 사람이
  누구인지 모두 안다. 인상관리(impression management) 편향이 기본값으로 깔려 있다.
- **PPT에 썼다.** 문단이 아니라 슬라이드다. 개조식·단문·불릿, 문장이 끊겨 있고,
  줄바꿈이 문법이 아니라 레이아웃을 따른다.
- **양식이 있었지만 안 지킨 사람이 섞여 있다.** 직급대별로 지시된 구성이 다르다:
  - **CL2·CL3** — 3단 구성이 원칙: ① 상반기 성과·하반기 전략 ② 커리어 회고·확보 역량
    ③ 미래 업무
  - **CL4** — 미래 위주 서술형
  - 원칙일 뿐이다. 헤더 없이 뒤섞어 쓴 사람, **"앞으로도 열심히 하겠습니다"로 끝낸
    사람**이 실제로 섞여 있다.
- **혼자 썼다.** 팀 단위 합의 문서가 아니라 200개의 독립적인 1인칭 서술이다.
  같은 일을 하는 두 사람이 그 일을 전혀 다른 단어로 부를 수 있다.

## 3. 텍스트 실물 — 합성 예시 4종

**아래는 전부 지어낸 것이다.** 다만 모양·길이·이탈 패턴은 실물과 같게 맞췄다.

### (a) 양식 준수 — CL2/CL3의 다수

```
1. 상반기 성과 및 하반기 전략
상반기에는 Advantest V93000 Test PGM 디버깅 시간 단축 업무를 맡아 성과를 냈다.
진행 과정에서 반복 수작업이 병목임을 확인했고, 이 경험이 하반기 계획의 출발점이 됐다.
하반기에는 STDF 기반 고장분석(FA) 자동화에 집중하려 한다.

2. 커리어 회고 및 확보 역량
현장 업무를 거치며 파이썬 데이터 분석 역량을 확보했고, 최근에는 STDF 파싱 자동화를
실무에 적용해 왔다.

3. 미래 업무
단기적으로는 STDF 기반 고장분석(FA) 자동화 체계를 만들고 싶다. 장기적으로는
DPPM 품질 개선을 위한 선제 진단까지 확장해, 팀이 재사용할 수 있는 기반을 만드는 것이 목표다.
```

### (b) 양식 미준수 — 흔한 이탈

```
올해는 MBT(Monitoring Burn-in Test) 신뢰성 강화 관련 일을 많이 했습니다.
ATE 스크립팅도 익혔고요. 앞으로 BIB(Burn-in Board) 설계·수명 관리를 해보고 싶은데
CLT 조건 정교화도 관심이 있습니다. 그동안 배운 통계적 공정관리(SPC)를 살려서 팀에
도움이 되면 좋겠습니다. 이것저것 하다 보니 정리가 잘 안 되네요.
```

### (c) CL4 — 미래 위주 서술형

```
앞으로의 방향
테스트 데이터(STDF) 통합 관리 체계를 팀 표준으로 자리잡게 하는 것이 목표다.
지금은 담당자마다 방식이 달라 결과를 한곳에서 비교하기 어렵다. 이를 위해 머신러닝
이상탐지와 설비 자동화 제어 역량을 확보해 왔다. 단기적으로는 D1b 신제품 램프업 기획
파일럿을 추진하고, 검증한 절차를 표준에 반영하는 것까지가 계획이다.
```

### (d) 무내용 — 전체의 대략 5~10%로 추정

```
그동안 여러 업무를 두루 경험했습니다. 앞으로도 팀에 보탬이 되도록 열심히 하겠습니다.
```

> (d)를 **버릴 노이즈로 볼지, 그 자체로 읽을 신호로 볼지가 첫 갈림길이다.**
> 누가 이렇게 쓰는지 — 어느 직급, 어느 조직에 몰려 있는지 — 는 질문이 될 수 있다.

## 4. 텍스트에 붙어 있는 것 — 메타데이터 네 줄

| 필드 | 값 | 비고 |
|---|---|---|
| `name` | 실명 | 200명 중 동명이인 가능 |
| `cl_level` | `CL2` / `CL3` / `CL4` | 직급대. 대략 주니어 / 중견 / 시니어~리더 |
| `pjt` | 상위 조직 3개 중 하나 | 예: 양산기술 / 공정기술 / 기획운영 |
| `part` | 세부 파트 | **없을 수 있다.** 있으면 pjt 하위 |

조직은 2단이고 **한쪽이 작다**. 상위 3조직의 인원 비중이 대략 4 : 4 : 2 수준이라,
"소수 조직에서만 나온 이야기"와 "전 조직에서 나온 이야기"가 처음부터 다른 무게를 갖는다.

직급 분포도 고르지 않다(대략 CL2 3 : CL3 4.5 : CL4 2.5). CL4는 인원이 적은데
**양식이 달라 미래 서술의 밀도가 가장 높다.**

## 5. 도메인 — 읽는 쪽이 모른다는 것을 전제해야 한다

후공정 테스트 도메인의 약어·고유명사가 문장마다 박혀 있다. 합성 예시에 나온 것만 해도:

```
STDF · ATE · Test PGM · Burn-in(MBT/BIB) · CLT · HFT · Yield · DPPM · FA
Advantest V93000 · Teradyne · Magnum · Handler · 병렬(Para) 테스트 · 멀티사이트
D1b(제품 코드) · SPC · 램프업
```

세 가지가 동시에 참이다:

1. **일반 임베딩·일반 LLM이 이 어휘를 모른다.** 한국어 일반 코퍼스에 거의 없다.
2. **같은 것을 여러 이름으로 부른다.** 약어/풀네임/한글표기/사내 은어가 섞인다.
3. **이 어휘가 신호의 대부분이다.** 이걸 뭉개면 남는 건 "열심히 하겠습니다"뿐이다.

여기에 더해 — **제품 코드명·장비명·사내 조직명은 그 자체로 대외비다.**
읽어낸 결과를 사내망 밖으로 내보내는 순간, 개인 이름보다 이쪽이 먼저 문제가 된다.

## 6. 물리적 조건

| | |
|---|---|
| 규모 | 약 200편, 각 300~1,200자. 전부 합쳐도 소설 한 권이 안 된다 |
| 언어 | 한국어 (약어·고유명사는 영문) |
| 갱신 | **없음.** 1회성. 작년치도, 다음 회차 예정도 없다 |
| 반출 | **불가.** 원문·이름·조직명 전부 사내망 밖으로 못 나간다 |
| 쓸 수 있는 것 | 사내망 LLM(OpenAI 호환), 임베딩 모델(BGE-M3), Elasticsearch(BM25 + kNN + 한국어 형태소 nori) |
| 못 쓰는 것 | 외부 API, 원문을 눈으로 보며 하는 튜닝 (설계자가 데이터를 못 본다) |

마지막 줄이 이 일의 가장 이상한 제약이다. **만드는 사람이 결과물을 눈으로 검증할 수 없다.**
"돌려보고 이상하면 고친다"가 성립하지 않는 상태에서 설계해야 한다.

## 7. 왜 이걸 뒤지고 있나

상사의 요구는 구두 한 문장이었다. 각색 없이 그대로:

> **"우리 팀 사람들이 쓴 근원경쟁력 기반으로, 우리 팀의 꿈이 담긴 향후 10년 로드맵"**

전달받은 전부가 이 한 줄이다.

그리고 **요구와 자료 사이에 정직한 간극이 있다:**

| 요구가 원하는 것 | 자료에 있는 것 |
|---|---|
| 10년 | 개인의 근미래(1~3년) 서술 |
| 시퀀싱(먼저·나중) | 순서 없음. "단기/장기"라는 말이 가끔 등장할 뿐 |
| 팀의 꿈 (단수, 하향식) | 200개의 1인칭 서술 (복수, 상향식) |
| 로드맵 (결정) | 재료 (관찰) |

**없는 것을 지어내면 그건 환각이다.** 동시에 "그러니 아무것도 못 한다"는 답도 아니다.
`10년`은 문자 그대로의 기간이 아니라 리더십 토론을 촉발하려는 해석 프레임에 가깝다고
본다 — 기간에 과몰입할 필요는 없다는 뜻이다.

**이 간극을 어떻게 정직하게 다룰 것인가가 사실상의 문제다.**

## 8. 이 텍스트가 답할 수 있는 것 / 없는 것

미리 정해둔 답은 아니고, 출발점으로 놓는 감각이다. **동의하지 않아도 된다** —
"이건 사실 답할 수 있다"고 반박하는 쪽이 오히려 반갑다.

**답할 수 있어 보이는 것**
- 무엇이 여러 사람 입에서 반복되는가
- 어떤 이야기가 조직 경계를 넘어 나오고, 어떤 것은 한 조직 안에만 머무는가
- 사람들이 "가졌다"고 쓰는 것과 "필요하다"고 쓰는 것의 차이
- 직급대에 따라 말하는 방식이 어떻게 달라지는가
- 한 사람만 말했지만 남들과 확연히 다른 이야기

**답할 수 없어 보이는 것**
- 언제 (시점·순서)
- 얼마나 중요한가 (본인이 중요도를 쓰지 않았고, 쓴 사람 수 ≠ 중요도)
- 실제로 할 수 있는가 (서술은 의지이지 역량 측정이 아니다)
- 쓰지 않은 것 (침묵은 부재인가 자명함인가)

**애매한 것 — 여기가 흥미롭다**
- 표현의 유사성이 실제 업무의 유사성인가, 같은 조직 어휘를 답습한 결과인가
- "열심히 하겠습니다"는 무성의인가, 쓸 말이 없는 상태인가, 안전한 선택인가

## 10. 그래서 — 무엇을 읽어낼 텐가

여기부터가 부탁이다. 아래는 방향 예시일 뿐, 목록을 채우라는 뜻이 아니다.
**전혀 다른 각도를 제안하는 쪽이 더 낫다.**

1. 200편을 다 읽은 사람이 아무도 없다. 한 사람의 머리에 안 들어가는 양은 아닌데,
   실제로는 아무도 안 읽었다. **읽었다면 알았을 것 중 무엇이 가장 아깝나?**
2. 같은 일을 다른 말로 쓰는 사람들과, 다른 일을 같은 말로 쓰는 사람들.
   둘 중 어느 쪽이 조직에 대해 더 많이 말해주나?
3. **침묵을 어떻게 읽나.** 아무도 쓰지 않은 것은 없는 것인가, 너무 당연한 것인가,
   말하기 곤란한 것인가. 텍스트 안에서 이 셋을 구별할 방법이 있나?
4. 직급대(CL2→CL3→CL4)를 따라 어휘·시제·주어가 어떻게 변하나.
   그 변화가 성장 경로처럼 보이나, 아니면 그냥 다른 양식의 결과인가?
5. 인상관리 편향을 **제거**하려 하지 말고 **측정**한다면? 안전한 문장과 위험한 문장의
   비율 같은 것이 조직 문화의 지표가 될 수 있나?
6. 개인이 쓴 "미래"들을 모으면 조직의 미래가 되나, 아니면 200개의 근미래를 더한 것은
   여전히 근미래인가? 이 질문에 텍스트로 답할 방법이 있나?
7. 이 자료의 **원저자 200명에게 되돌려준다면** 무엇을 돌려줘야 각자에게 쓸모가 있나?
   (조직에 보고하는 산출물과 본인에게 돌려주는 산출물은 같은 물건일 수 없다)
8. 결과를 검증할 사람이 원문을 못 본다면, **무엇을 근거로 "이 결과가 맞다"고 말할 수 있나?**
   추적 가능성을 어디까지 설계해야 하나?
9. 200편·1회성이라는 규모에서, 통계는 어디까지 유효한가. 17명과 2명의 차이는 신호인가 잡음인가?
10. 상사의 한 문장("꿈이 담긴 10년 로드맵")에 **정직하게** 답한다면, 최종 산출물은
    문서인가, 화면인가, 회의인가, 아니면 질문 목록인가?

## 부록 — 이 자료로 이미 한 번 해본 것 (기법 하나, 코드 포함)

앵커링을 피하려 본문에서는 뺐지만, **한 가지는 이미 해봤고 결과물이 무대에도 올라갔다.**
같은 텍스트를 사람 단위로 임베딩해 서로 얼마나 닮았는지 그린 것이다.

방식은 단순하다. 1인 1벡터 → 전원 코사인 유사도 → 인당 상위 K명만 저장 →
브라우저에서 힘-기반 그래프로 배치. **계산은 전부 빌드 타임**이고 화면은 미리 계산된
JSON만 읽는다(발표장 네트워크가 죽어도 로컬 파일로 돌아간다).

```
neighbors.json: { "<사람id>": [ { "id": 이웃id, "similarity": 0.87 }, ... ] }
```

```python
"""임베딩 벡터 → 코사인 유사도 top-K 이웃 neighbors.json 변환.

입력: {인물id: 벡터} JSON (차원은 입력에서 유추).
"""
import json, math, sys
from pathlib import Path
from config import K            # K = 30 (인당 저장 이웃 수)

ROOT = Path(__file__).parent.parent


def top_k_neighbors(embeddings, k=K):
    """{id: 벡터} → {str(id): [{"id", "similarity"}, ...]} (내림차순, 자기 자신 제외)."""
    ids = list(embeddings)
    unit = [[x / math.hypot(*embeddings[i]) for x in embeddings[i]] for i in ids]
    out = {}
    # ponytail: 순수 파이썬 O(n²·d) — 수백 명 규모 빌드 타임엔 충분, 수천 명이면 numpy로
    for a, i in enumerate(ids):
        scored = [
            (round(math.sumprod(unit[a], unit[b]), 4), ids[b])
            for b in range(len(ids)) if b != a
        ]
        scored.sort(key=lambda t: (-t[0], t[1]))     # 동점이어도 순서가 결정적이게
        out[str(i)] = [{"id": j, "similarity": s} for s, j in scored[:k]]
    return out


def main(emb_path, out_path=ROOT / "data" / "neighbors.json"):
    embeddings = {int(i): v for i, v in json.loads(Path(emb_path).read_text()).items()}
    Path(out_path).write_text(
        json.dumps(top_k_neighbors(embeddings), ensure_ascii=False, indent=1))
    return out_path
```

짧고 강한 줄**) + 중앙 인력 + 감쇠, 한 틱이 전부다:

```javascript
  var repulseK = 900 * (W / 1400);

      n1.vx += (dx/dist)*f; n1.vy += (dy/dist)*f;
      n2.vx -= (dx/dist)*f; n2.vy -= (dy/dist)*f;

  }
```

```javascript
function egoTargets(id){
  var neighbors = adjacency[id].slice(0, EGO_N);
  var cx = W/2, cy = H/2;
  var entries = [{ node: byId[id], tx: cx, ty: cy, tr: 15 }];
  neighbors.forEach(function(nb, i){
    var angle = (i / Math.max(neighbors.length, 1)) * Math.PI * 2 - Math.PI/2;
    var dist = Math.max(70, Math.min(235 - nb.w * 150, Math.min(W, H) * 0.42));
    entries.push({ node: nb.node, tx: cx + Math.cos(angle)*dist, ty: cy + Math.sin(angle)*dist,
                   tr: 6 + Math.max(nb.w, 0) * 13 });
  });
  return { neighbors: neighbors, entries: entries };
}
```

**이 접근이 실제로 준 것과 안 준 것:**

- 준 것 — 사람들이 **자기 이름을 찾고 닮은 동료를 눌러보게** 만들었다. 200명 앞 무대에서
  통했고, 이후에도 상시 접근 가능한 아카이브로 남았다.
- 안 준 것 — **"그래서 조직이 어디로 가야 하나"에는 한 글자도 답하지 못한다.**
  닮음은 관계지 방향이 아니다. 노드는 사람이고, 사람은 주제가 아니다.

이걸 굳이 붙여둔 이유는 하나다 — **이 자료로 할 수 있는 일이 "분류해서 요약한다"
말고도 있다는 증거**이기 때문이다. 같은 텍스트가 무대 위 10분짜리 경험도 됐다.
