> 상태: 행사 구성 확정. 다음 단계는 PRD 작성(별도 요청 예정) 및 코드 구현.
> 이 문서는 다른 세션의 에이전트가 이어받을 수 있도록 확정 사양 + 맥락을 담는다.

- Jay(AIX 역할)가 사내 분기 전체회의에서 10분 AI 세그먼트 담당
- 장소: 강당, ~200명, 제조업 HW개발/설비운영 인원(비개발자 다수), PC + PPT
- 분기회 전체는 1시간(추첨/퀴즈 등 기존 순서 있음), 그중 10분이 Jay 코너
- 목적: 교육 아닌 경험/오락. AI 친숙한 인상 + 분위기 업 + AX 조직 존재감(암묵적 홍보)
- 홍보 원칙: 슬라이드 홍보 금지. 경험 자체 + 클로징 한 줄로만 처리

- **근원경쟁력**: 부서원들이 각자 커리어를 돌아보며 쓴 회고 자료. CL2/CL3/CL4 세 개의 PPT 파일, 인당 2~3페이지, 총 ~150명. PPT 상단에 작성자 이름 있음
- 주보(주간보고) 데이터는 소재에서 제외됨 — 근원경쟁력 단일 소재로 통일
- 자료 신뢰함(품질 의구심 불필요), 프라이버시 이슈 없음(이전 직장 이력 등 신경 안 씀), 내용은 기술적 서술 위주라 워드클라우드/유사도 결과 민망할 위험 낮음

## 3. 무대 구성 (확정 타임테이블)

| 시간 | 코너 | 내용 | 도구 |
|---|---|---|---|
| 0:00–1:00 | 오프닝 + 워드클라우드 리빌 | "여러분이 쓴 근원경쟁력, AI가 다 읽었습니다" → 전체 워드클라우드 등장. 훅 용도, 오래 머물지 않아도 됨 | PPT → Archive |
| 1:00–5:30 | 유사도 네트워크 | 본인 이름 검색 2~3명 → 에고 뷰(닮은꼴 top-10 궤도) 리빌, 엣지에 공통 태그 라벨, 클릭 시 유사군 워드클라우드 연동, 팀 필터 시연 | Archive |
| 5:30–8:00 | The Higher The Lower | 근원경쟁력 단어 빈도 10문제 연속, 정답자 경품. 분위기 최고조에서 배치 | Aha Slides |
| 8:00–10:00 | 클로징 | RAG 등 "이런 것도 하고 있다" 소개(Jay 재량, 별도 데모 코너 아님) + Archive 공지 + "관심 팀 연락주세요" | PPT |

### 구성 관련 확정 사항
- 진행자: **1인** (Jay)
- 게임 형식: **1라운드 10문제 연속** (한 문제 8~10초, 총 2분 30초 예상). 우승자 검색 코너 없음
- 게임을 뒤에 배치한 이유: 처음부터 게임이면 "읭" 반응 우려. 클라우드(신기) → 네트워크(몰입) → 게임(폭발) → 클로징 에너지 곡선
- 워드클라우드 선공개 스포일러 이슈: 클라우드는 상대 크기만 보여주고 절대 횟수는 안 보임 → **횟수 맞추기(제시 숫자 대비 업/다운) 유형이면 스포 무관**. 단어 대결 유형은 크기 비슷했던 쌍으로 출제하면 오히려 재미. 팀별/CL별 출제는 전체 클라우드와 데이터가 달라 스포 무관
- RAG: 무대 라이브 데모 **하지 않음**. 클로징에서 소개만. RAG 자체는 별도 사내 UI 존재, 이 프로젝트 스코프 밖
- QR/현장 즉시 오픈 **안 함**. Archive는 공지로
- 경품 지급: 게임 후 바로 처리
- 룰렛 기믹 금지 (이전 GiftRoulette로 식상)
- 라이브 AI 호출 금지 원칙 유지 (강당 네트워크 리스크) — Archive는 런타임 API zero라 무관

## 4. Heritage Archive (배포물) 사양

- **형태**: 정적 단일 HTML (모든 데이터 JSON 인라인, wordcloud2.js 등 라이브러리도 인라인 권장)
- **호스팅**: 사내 GitHub Pages (사내망이라 보안 무관). 발표 당일 로컬 파일 백업 병행
- **네이밍**: "Heritage Archive" (heritage = 팀 내 통용 용어). 대안 후보로 Heritage Map 등 언급됐으나 확정은 사용자 몫
- **모바일 대응 불필요** (현장 오픈 안 하므로)

### 기능
1. **유사도 네트워크** (기존 프로토타입 `similarity-network-prototype.html` 기반 — 프로젝트 파일에 있음)
   - 150명 실데이터, force-directed 캔버스, 팀별 색상/글로우
   - 이름 검색, 팀 필터(클릭 dim/더블클릭 isolate), Top-N 슬라이더(2~12)
   - 인물 클릭 → 에고 뷰: 유사도 top-10 궤도 배치, 순차 리빌 애니메이션
2. **동적 워드클라우드** (신규)
   - wordcloud2.js (캔버스 기반, 한글 OK)
   - 전체 / 팀별 / CL별 / 유사군별(에고 뷰 선택 인물 + top-N 이웃 빈도 합산)
   - 원리: 인당 단어 빈도 딕셔너리를 JSON에 사전 저장 → 브라우저에서 선택 집합 빈도 합산(단순 덧셈) 후 재렌더. 150명×수백 단어 수준이라 성능 문제 없음
   - 소집단 클라우드 빈약 방지: 합산 최소 인원 5명 권장
3. **태그** (신규)
   - 인물 디테일 패널에 태그 칩
   - 태그 필터: 클릭 시 보유자 점등, 나머지 dim (기존 팀 필터와 동일 UX)
   - 에고 뷰 엣지 라벨: 두 사람의 공통 태그 표시 (공통 태그 있을 때만 — 유사도 높아도 공통 태그 0개인 쌍 존재)
   - 태그를 노드로 만드는 이분 그래프는 기각 (헤어볼)
4. **인물 카드**: 인당 회고 텍스트(md) 렌더. PPT 페이지 이미지 export는 **제외** (확정)

## 5. 데이터 파이프라인

### 역할 분담
- **Jay 담당**: PPT 3개 파싱 → 인당 텍스트(md 또는 df), 사내 임베딩 API 호출
- **Claude/에이전트 담당**: 아래 코드 + Archive HTML

### 빌드 타임 처리 흐름 (런타임 API 호출 zero)
```
인당 텍스트 (Jay가 md/df로 전달)
 ├─ ① 형태소/빈도 집계 → 인당+전체 빈도 JSON, 게임 문항 후보
 ├─ ② (Jay) 임베딩 → ③ 코사인 유사도 → 인당 top-12 이웃 JSON
 └─ ④ LLM 태그 추출 → 태그 JSON
```

### 태그 추출 방식 (확정)
- **1인 1호출 × 150회 배치** (긴 컨텍스트 1방 아님). 인당 2~3p ≈ 수천 토큰
- 개별 호출 이유: 간섭 없음, 실패 시 개별 재시도, JSON 파싱 단순
- **자유추출 + 간단 정규화(동의어 병합)만** — 정식 2-pass vocabulary/계층화/온톨로지 제안서는 v2로 이관 (분기회 후)
- 정규화는 추출 완료 후 태그 풀 전체를 1~2회 LLM 호출로 정리
- 무대에서 태그 추출 과정은 노출하지 않음 (에고 뷰 엣지 라벨로만 자연 노출)

### 데이터 인터페이스 (제안됨, 미확정)
```
persons.json: id, name, team, cl_level, text(인당 전문), tags
neighbors: 인당 top-12 [{id, similarity}]
freq: 인당 {단어: 횟수}
```
- 임베딩: 인당 1벡터 권장 (2~3p 합산). 차원수는 사내 API 스펙 확인 필요

## 6. 작성할 코드 목록 (확정 스코프)

1. 형태소/빈도 집계 스크립트 (kiwipiepy 등, 명사 위주, 커스텀 불용어 리스트 — 불용어 품질이 워드클라우드 인상 좌우)

4. Archive HTML 확장 (기존 프로토타입 + 워드클라우드 + 태그 + 인물 카드 통합)
