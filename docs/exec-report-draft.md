# 임원 보고 초안 (SW 비전공 대상, 텍스트 보고용)

**큰 접근**
개별 엔지니어가 각자 써온 "근원경쟁력"을, 개인이 아니라 팀 단위에서 이해해보려는
시도다. 지금까지는 한 사람 한 사람의 회고로만 존재해서 개인 안에 갇혀 있던 것을,
AI로 폭넓게 분석해 사람이 150명분을 일일이 대조하지 않고는 보기 힘든 연결 — 비슷한
역량을 가진 동료, 조직이 쏠리는 방향, 미처 몰랐던 소수 의견 — 을 찾아 팀 차원의
그림으로 보여주는 것이 목표다.

**배경**
- 부서원 150명이 분기마다 "근원경쟁력" 회고를 이미 개인별로 작성해 둔 자산이 있음
- 지금까지는 개인 단위로만 존재해서, 전체를 모아 보면 조직이 어디로 가고 있는지 새롭게 보일 여지가 있음
- 이 자산을 활용해 ① 엔지니어 개개인의 역량을 서로 연결하고 ② 조직이 지금 뭘 중요하게 여기는지 진단해보자는 시도

**한 것 — Heritage Archive**
- 150명 회고 텍스트를 정리 → 비슷한 역량끼리 자동으로 묶어 "나와 닮은 동료" 지도로 시각화
- 분기회 무대에서 라이브 시연, 이후 사내 페이지로 상시 공개해 본인이 직접 검색 가능

**하고 있는 것 — task-discovery**
- 같은 회고 글에서 이번엔 "역량"이 아니라 팀원이 직접 쓴 "앞으로 하고 싶은 일" 문장만 추출
- 주제별로 묶어서 조직이 쏠리는 큰 흐름 몇 가지 + 소수지만 눈에 띄는 특이 의견을 정리
- 더미 데이터로 검증 완료, 실데이터 적용 시작

**실데이터 적용 첫 결과 — 기대치 조정 필요**
- 실제 회고로 돌려보니 두 지점에서 품질이 기대에 못 미침: ① 추출된 "할 일" 문장이
  너무 단편적(한 줄 요약 수준)이라 정보가 얕음 ② 비슷한 주제끼리 묶는 자동 그룹핑이
  아직 사람이 보기에 신뢰할 만큼 깔끔하지 않음
- 원인 후보를 좁혀 다음 단계로 넘김 — 문장을 뽑는 방식(프롬프트) 보완, 그리고 애초에
  "문장 하나하나"로 잘게 쪼개는 것보다 "사람 한 명의 미래 계획 덩어리" 단위로 다루는
  게 더 안정적일 수 있어 그 대안도 함께 검토 중
- 결론: 이번 결과물을 그대로 공개하기엔 이르고, 원인 검증 후 재시도 필요 (상세는
  `docs/task-discovery-realdata-findings.md`)

**다음 단계 — 큰 방향**
- 지금은 "비슷한 문장끼리 자동으로 알아서 묶는" 방식인데, 사내 전문 용어를 잘 몰라
  묶음이 부정확해지는 게 확인됨
- 다음으로는 전문 용어를 아는 사람이 먼저 카테고리 틀을 정해주고, 그 틀에 맞춰
  분류하는 방식을 검토 — 자동 발견보다 안정적이고 설명하기 쉬운 결과를 기대
- 세부 검토는 실무 문서에서 계속 진행 (`docs/task-discovery-realdata-findings.md`)
