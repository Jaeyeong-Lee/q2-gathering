부록 2 · 과제 정의 — 왜 전수 자동 분석인가

1페이지 「무엇을 했는가」의 근거 — 이 방식을 택한 이유

요구는 팀 단위, 데이터는 개인 단위다.

자료 200건은 각자가 자기 프로젝트 맥락에서 쓴 개인·근미래 서술이다. 팀 차원의 방향은 어느 자료에도 직접 적혀 있지 않고, 200건을 종합해야 나온다.

종합을 사람이 수행할 경우의 문제
기준 일관성 200건을 동일한 잣대로 판단하기 어렵다. 읽는 순서와 피로도가 결과에 개입한다.
소수 의견 소실 요약은 본질적으로 다수를 남기고 소수를 버린다. 1~2명이 제기한 방향은 정리 과정에서 사라진다.
근거 추적 종합 결과에서 개별 원문으로 되돌아가기 어렵다.
따라서 목표를 다음과 같이 설정했다
  1. 200건 전수를 동일 기준으로 처리한다
  2. 소수 의견을 별도로 보존한다
  3. 모든 결과를 원문 인용으로 역추적 가능하게 한다

처리 시간 단축이 목적이 아니다. 사람이 수행할 경우 품질이 담보되지 않는 부분을 자동 처리에 맡긴 것이다. 반대로 자동 처리가 담보하지 못하는 부분은 부록 7에 정리했다.

부록 3 · 처리 방식 — 5단계 분석 과정

1페이지 「현황 — 완료」의 근거 — 구축을 마친 대상이 무엇인가

단계처리 내용 산출물자동 분석 질의
① 추출 자료 원문에서 과제·역량·방향을 항목으로 뽑아낸다 작성자별 추출 항목과 근거 문장 약 200회
② 분류 체계 유사한 항목을 묶어 카테고리를 정의한다 카테고리 목록 (초안) 약 30회
③ 배정 추출된 항목을 카테고리에 배정한다 항목–카테고리 대응표 약 600~800회
④ 집계 카테고리별 인원과 역량 확보 여부를 산출한다 집계표 없음
⑤ 정리 열람 가능한 문서로 생성한다 검토용 정리 문서 없음

전 단계를 사내망 전용 언어모델로만 처리한다. 총 질의량은 약 1,000회다.

단계별 중간 결과를 모두 보존한다

특정 단계의 결과가 잘못되면 그 단계부터 다시 실행할 수 있고, 앞 단계는 재실행하지 않는다. 처리가 중간에 중단되어도 중단 지점부터 재개된다.

②단계가 선행 조건인 이유

질의량이 가장 큰 구간은 ③ 배정이다. 분류 체계가 바뀌면 이 단계를 전부 다시 수행해야 하므로, 체계 확정이 선행되어야 한다. 표에서 색으로 표시한 ②단계가 1페이지의 「진행 중」 항목이다.

④·⑤단계는 언어모델을 쓰지 않는 산술과 문서 생성이다. 같은 입력에 대해 결과가 매번 동일하다.

부록 5 · 신뢰성 확보 — 확인 가능한 구간의 장치

1페이지 「핵심 판단」의 근거 — 「확인 가능」 쪽이 실제로 어떻게 확인되는가

자동 분석 결과를 그대로 신뢰할 수 없으므로 네 가지 장치를 두었다.

① 원문 대조

근거 문장이 해당 자료 원문에 실제로 존재하는지 대조한다. 존재하지 않으면 만들어진 문장이므로 폐기한다.

② 인용 복제 차단

정리한 서술이 원문을 그대로 옮긴 것에 불과한 경우 폐기한다.

③ 항목 단위 폐기

①·② 위반 시 해당 항목만 버리고 다시 질의한다. 자료 한 건 전체를 버리지 않는다. 재질의 후에도 통과하지 못하면 유효한 항목만 보존한다.

④ 처리 결과 공개

전체 대상 중 「신호 없음」으로 처리된 건수와 「기타」로 분류된 건수를 함께 보고한다. 소수 인원이 제기한 카테고리는 다수 집계에 흡수되지 않도록 별도 트랙으로 보존한다.

결과적으로, 추출 단계 산출물의 모든 문장은 원문 대조를 통과한 것이다.

①·②는 사람의 표본 검사가 아니라 전 건에 대해 자동으로 수행되는 절차다. ④의 수치는 실행 결과가 나오는 대로 그대로 공개한다. 처리하지 못한 비율을 감추지 않는 것이 전제다.

분류 명칭 · 시점 판정불가 원문에 정답이 존재하지 않는다.
분류 체계 — 카테고리 명칭과 경계

사용 모델은 당사 도메인 지식을 갖고 있지 않다. 사내 용어를 일반 용어로 치환하거나, 조직 감각과 맞지 않는 경계로 묶는 사례가 발생한다. 자동으로 확인되는 것은 분류 구조의 형식적 정합성뿐이며, 명칭의 타당성은 판정되지 않는다.

사례: 자동 생성된 명칭 → 실제 사용하는 용어

시점 판정 — 단기 / 장기

자료에 시점을 명시한 작성자가 거의 없다. 현재 값은 추정이며, 원문으로 검증할 수단이 없다.

이는 모델 성능을 높여 해결되는 문제가 아니다. 판단 근거가 데이터에 없는 구조적 문제다. 따라서 이 두 지점은 처음부터 사람이 확정하는 것으로 설계했다.

대응 — 도메인 검증 절차

전수 검토는 하지 않는다. 자동 확인이 성립하지 않는 지점에만 사람이 개입한다.

검토 대상은 카테고리 수십 개 수준이지 자료 200건이 아니다.

탐색기특정 수치의 근거 원문 확인
