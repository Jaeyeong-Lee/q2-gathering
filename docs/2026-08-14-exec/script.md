## 1. 과제 정의

**표시 내용**

**PPT 600장 이상 검토, 종합 — 사람 대신 AI 수행**

**종합을 사람이 수행할 경우의 문제**

| 문제 | 내용 |
|---|---|
| 기준 일관성 | 240건에 동일 잣대 적용 곤란, 읽는 순서와 피로도 개입 |
| 소수 의견 소실 | 요약 과정에서 다수만 잔존, 1~2명이 제기한 방향은 탈락 |
| 근거 추적 | 종합 결과 → 개별 원문 역추적 곤란 |

**CL별 자료 구성**

- CL2·CL3 — ① 상반기 성과·하반기 전략 ② 커리어 회고·확보 역량 ③ 미래 업무
- CL4 — 미래 위주 서술형

> 각 Engineer가 치열하게 고민해 작성한 자료 240건 —
> **AI가 한 건도 빠뜨리지 않고 읽어** 팀의 방향성으로 재구성

**구두 보충**
- 형식 미준수 문서가 섞여 있어, 정형 파싱이 아니라 자연어 이해가 필요했다.
- 반대로 기계가 담보하지 못하는 부분은 6장에서 따로 말씀드린다.

## 2. 처리 방식

**표시 내용**

**PPT 원문 → 텍스트 → 5단계 파이프라인**

작성자 240명의 PPT 파일을 사내 문서 변환 시스템 **Docpamin**으로 텍스트화한 뒤 파이프라인에 넣는다.
④ 집계와 ⑤ 정리는 LLM을 쓰지 않는 산술·문서 생성이라 흐름도에서 한 칸으로 묶었다.

| 단계 | 처리 내용 | LLM 호출 |
|---|---|---|
| ① 추출 | 자료 원문에서 과제·역량·방향 항목화 | 자료 1건 = 1회 · 약 200회 |
| ② 분류 체계 | 유사 항목을 묶어 카테고리 정의 | 항목 30개 = 1회 · 약 100회 |
| ③ 배정 | 추출 항목을 카테고리에 배정 | 항목 1개 = 1회 · 약 3,000회 |
| ④ 집계 | 카테고리별 인원·역량 확보 여부 산출 | 없음 |
| ⑤ 정리 | 열람 가능한 문서로 생성 | 없음 |

②는 LLM이 초안을 만들되 사람이 확정하는 단계다 (6장).

**구두 보충**
- ④·⑤단계는 LLM을 쓰지 않는 산술·문서 생성이다. 결과가 매번 동일하다.
- 호출량이 큰 구간은 ③ 배정이다. 분류 체계가 바뀌면 이 단계를 다시 돌려야 하므로, 체계 확정이 선행되어야 한다.

## 3. 미래 과제·역량 추출

**표시 내용**

**자료 1건당 4개 축 추출 — 240명 전부 동일 질문 적용**

| 축 | 내용 |
|---|---|
| 미래 과제 | 앞으로 수행하려는 업무 (+ 시점: 단기/장기/불명) |
| 보유 역량 | 이미 확보했다고 서술한 역량 |
| 필요 역량 | 부족하거나 필요하다고 서술한 역량 |
| 지향 방향 | 전반적 방향 |

**실제 프롬프트** (자료 1건 별)

```
다음은 (작성자)(CL3, 프로젝트/파트)의 근원경쟁력 회고다.
3단 구성(①상반기 성과·하반기 전략 ②커리어 회고·확보 역량
③미래 업무)이 원칙이나 미준수 문서도 있다.
미래과제 · 보유역량 · 필요역량 · 지향방향을 추출하라.

형식: {"signal_present": true/false,
 "future_task": [{"text": …, "horizon": "단기|장기|불명",
                  "quotes": ["원문 발췌"]}], …}

규칙: quotes는 반드시 원문에서 글자 그대로 발췌한다.
text는 quote의 복사가 아니라 서술이어야 한다.
내용이 없으면 signal_present=false 로 하고 축을 비운다.
원문:
(PPT에서 뽑아낸 텍스트 전체)
```

**항목마다 근거 문장을 함께 보관한다**

- `text` — 정리된 서술
- `quotes` — 그 서술의 근거가 된 **원문 그대로의 문장**

**내용이 없는 자료는 별도 표시한다.**
서술이 사실상 없는 자료를 임의 분류하지 않고 `신호 없음`으로 분리한다.

**구두 보충**
- 시점(단기/장기)은 작성자가 명시한 경우가 드물어 상당수가 추정값이다. 이 부분은 6장에서 다시 다룬다.

## 4. 분류 체계 유도

**표시 내용**

**반복 구조** (다이어그램)

추출 항목(과제 · 역량 · 방향) → 30개씩 잘라 순서대로 → **만들어지는 분류표**
→ 카테고리 간 관계 정리(맨 마지막 1회) → **완성된 분류표 — HITL, 사람이 확정**

마지막 상자에 붙는 주석: 앞 회차의 잘못된 카테고리가 뒤 회차로 그대로 누적되므로
**사람이 확정한다.**

| 회차 | 분류표 |
|---|---|
| 1회차 | 첫 초안 |
| 2회차 | 합치기 · 쪼개기 · 정의 수정 |
| … | |
| n회차 | 카테고리 15~25개 |

**고쳐진 분류표를 다음 회차에 다시 준다.**

**매 회차 AI에게 건네는 것**

| 구분 | 내용 |
|---|---|
| 지금까지 만든 분류표 | 카테고리 이름 · 뜻 · 여기에 들어오는 항목의 기준 — **직전 회차가 돌려준 것 그대로** |
| 아직 안 읽힌 항목 30개 | 순서대로 다음 차례가 오는 30개 |
| 요구 | 이 30개를 반영해 **분류표 전체를 다시 써 달라.** 같은 뜻의 카테고리를 둘로 만들지 말 것 |

돌려받는 것 — **고쳐 쓴 분류표 전체**. 다음 회차의 첫 줄
컨텍스트 용량 한계로 분할 진행

**실제 프롬프트** (2회차 이후)

```
너는 팀의 근원경쟁력 회고에서 뽑은 항목들을 읽고,
역량/방향 카테고리를 만든다. 개수는 고정하지 말고
데이터가 요구하는 만큼(대략 15~25개).
각 카테고리는 이름 · 정의(1문장) · 포함 기준을 갖는다.

기존 분류표(병합·분할·정제 대상):
[{"name": …, "definition": …, "inclusion_criteria": …}, …]
새 항목들:
- (31번째 항목)   - (32번째 항목)   …

기존을 갱신한 전체 분류표를 반환하라 (중복 금지).
```

**구두 보충**
- 미리 만든 카테고리 목록이 없다. 틀을 먼저 정하면 자료에 없는 칸에 억지로 맞추게 되므로, 개수를 고정하지 않고 데이터가 요구하는 만큼 만든다.
- 배치 하나가 실패하면 거기서 멈춘다. 건너뛰면 그 30개가 빠진 채로 정상 완료된 것처럼 보인다.
- 카테고리 간 관계는 반복 중간에 매기지 않고 맨 마지막에 한 번만 뽑는다. 중간에 매기면 아직 만들어지지도 않은 카테고리를 가리키게 된다.

## 5. 산출물 예시 — 시간 × 역량 확보 매트릭스

**표시 내용**

| 축 | 정의 | 결정 주체 |
|---|---|---|
| 가로 — 시간 | 단기 · 중기 · 장기 | **사람이 확정** (초안은 자동 생성) |
| 세로 — 역량 확보 | 필요 언급 대비 보유 언급 비율 | 데이터가 결정 (고정) |

- 버블 크기 = 해당 카테고리를 언급한 인원수
- **좌상단 = 시급하나 역량 미확보** — 우선 검토 대상
- 우하단 = 역량은 확보되어 있으나 장기로 분류된 항목 — 시점 재검토 대상
- **역량 언급이 없는 카테고리는 축 밖 별도 표시** — 판정 불가로 두고, 확보로 처리하지 않는다

> 세로축 — **부족하다**는 서술이 많으면 위, **갖췄다**는 서술이 많으면 아래. **자료 발췌 기준**

| 구분 | 값 |
|---|---|
| 단기 / 중기 / 장기 | [[8]] / [[7]] / [[5]] (예시) |
| 판정 불가 (축 밖) | [[3]]건 (예시) |

**구두 보충**
- 세로축을 인원수와 섞지 않았다. 인원수는 버블 크기가 이미 표현하므로 축에서 제외했다.
- 가로축은 초안일 뿐이다. 확정은 6장의 향후 계획에서 이뤄진다.

## 6. 한계 및 향후 계획

**표시 내용**

**LLM 호출 3단계 중 결과 검증 가능 2단계**

| 단계 | 검증 코드 | 의미 |
|---|---|---|
| 추출 | `td_extract.py` · 12건 | 뽑은 문장이 원문에 있는지 대조 |
| 배정 | `td_assign.py` · 10건 | 배정 근거를 인용으로 확인 |
| **분류 체계** | `td_taxonomy.py` · **0건** | **대조할 원문이 존재하지 않는다** |

도메인 지식 부재 — **카테고리 명칭·경계**와 **시점 판정** 확정 불가.
**판단 근거가 데이터에 없는 구조적 제약**

**향후 계획** — 우측 상단에 `최종 9월 완료 예정` 배지

| | 계획 | 기대 효과 |
|---|---|---|
| 1 | **도메인 지식을 추가 전달**해 추출·분류 재수행 | 사내 용어에 맞는 카테고리 명칭 확보 |
| 2 | **프롬프트 최적화** | 누락·오분류 감소, 회차 누적 오류 완화 |
| 3 | **직무 전문가 의견 청취** | 카테고리 경계와 시점 판정 확정 |
| 4 | 필요 시 **워크숍 진행 검토** | 우선순위 설정 |

**구두 보충**
- 모델 성능을 높여 해결되는 문제가 아니다. 판단 근거가 데이터에 없다.
- 자료에 시점을 명시한 작성자가 거의 없어, 현재 시점 값은 모델의 추정이다.
