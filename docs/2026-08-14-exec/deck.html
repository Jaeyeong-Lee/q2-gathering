3. 미래 과제·역량 추출

자동 검증

자료 1건당 4개 축 추출 — 240명 전부 동일 질문 적용

축내용
미래 과제앞으로 수행하려는 업무
+ 시점: 단기 / 장기 / 불명
보유 역량이미 확보했다고 서술한 역량
필요 역량부족하거나 필요하다고 서술한 역량
지향 방향전반적 방향
실제 프롬프트 — 자료 1건 별
다음은 (작성자)(CL3, 프로젝트/파트)의 근원경쟁력 회고다. 3단 구성(①상반기 성과·하반기 전략 ②커리어 회고·확보 역량 ③미래 업무)이 원칙이나 미준수 문서도 있다. 미래과제 · 보유역량 · 필요역량 · 지향방향을 추출하라. 형식: {"signal_present": true/false, "future_task": [{"text": …, "horizon": "단기|장기|불명", "quotes": ["원문 발췌"]}], …} 규칙: quotes는 반드시 원문에서 글자 그대로 발췌한다. text는 quote의 복사가 아니라 서술이어야 한다. 내용이 없으면 signal_present=false 로 하고 축을 비운다. 원문: (PPT에서 뽑아낸 텍스트 전체)
항목마다 근거 문장을 함께 보관

text — 정리된 서술

quotes — 그 서술의 근거가 된 원문 그대로의 문장

내용이 없는 자료는 별도 표시

서술이 사실상 없는 자료를 임의 분류하지 않고 「신호 없음」으로 분리한다.

04

4. 분류 체계 유도

사람이 확정할 단계
매 회차 AI에게 건네는 것
지금까지 만든 분류표 카테고리 이름 · 뜻 · 들어오는 항목의 기준 — 직전 회차가 돌려준 것 그대로
안 읽힌 항목 30개 순서대로 다음 차례가 오는 30개
요구 이 30개를 반영해 분류표 전체를 다시 써 달라

돌려받는 것 — 고쳐 쓴 분류표 전체. 다음 회차의 첫 줄

컨텍스트 용량 한계로 분할 진행

실제 프롬프트 — 2회차 이후
너는 팀의 근원경쟁력 회고에서 뽑은 항목들을 읽고, 역량/방향 카테고리를 만든다. 개수는 고정하지 말고 데이터가 요구하는 만큼(대략 15~25개). 각 카테고리는 이름 · 정의(1문장) · 포함 기준을 갖는다. 기존 분류표(병합·분할·정제 대상): [{"name": …, "definition": …, "inclusion_criteria": …}, …] 새 항목들: - (31번째 항목) - (32번째 항목) … 기존을 갱신한 전체 분류표를 반환하라 (중복 금지).
