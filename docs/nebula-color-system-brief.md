# 작업: 성운 3계층 색 체계 — PJT 배경 안에서 과제군·과제별 색 변형

> Jay 확정(2026-09-14): "PJT별 배경색 안에 과제별로도 색을 나눈다."
> 실제 성운 사진의 색 구조를 따른다 — 성운 전체에 지배 색조 하나 + 그 안에서 밀도·에너지의
> 색조 변주 + 뜨거운 별만 다른 색. 8색 랜덤 무지개가 아니라 **절제된 변주**.

## 3계층 설계

### 계층 1 — PJT 배경 성운 (지배 색조, 기존 유지)
- 기존 8색 팔레트(#7dcfff 등) 그대로. `nebula()` 가스 렌더의 저투명도 배경.
- "여기가 어느 PJT 영역인가"의 영역 표시. 격자 화면(장면 2 기본)에서도 이 색 유지.

### 계층 2 — 과제군(taxonomy)별 색조 변형 (핵심 신규)
- 같은 PJT 안의 5개 과제군이 **PJT 지배 색조의 변주**를 가진다:
  - hue ±15~20도 씩 미세 조정, 또는 lightness/chroma 5단계
  - 예: 기술기획(#7dcfff) → 5개 과제군이 파랑빛 강한 것 → 밝은 것 → 옅은 것 → 회청색 → 거의 흰색
- 계산은 **빌드 타임**: 과제군별 색 테이블을 payload에 추가 (또는 CSS `color-mix()` 런타임, Chrome 111+)
- 효과: 같은 PJT 안에서 과제군이 **무리지어** 보임 — 실제 성운의 가스 뭉치 색조 변주와 동일.
  과제군 품질도 시각적으로 검증 가능 (묶음이 색으로 읽힘).

### 계층 3 — 개별 과제 별 (horizon = 밝기)
- 과제는 소속 과제군의 색조를 따르되, **horizon으로 lightness 변주**:
  - 단기 = 가장 밝고 뜨겁게 / 중기 = 중간 / 장기 = 어둡고 깊게 / 시점 미명시 = 가장 흐릿하게
- "뜨거운 별": 클로즈업·선택된 과제만 순백 + 글로우.
- **축 분리 원칙 (중요)**: 과제군 = hue 변형, horizon = lightness. 두 축이 섞이면 읽을 수 없다.

## 구현 포인트

- `color()` 함수(nebula.html 72행, `color = t → D.pjts[t.pjt].color`)를 `color(t, mode)`로 확장:
  - `mode: 'pjt'` — 기존 동작 (장면 2 격자, PJT 격자 라벨, d3-log 계열 색 일관성 필요한 곳)
  - `mode: 'nebula'` — 계층색 (PJT 성운 안에 들어갔을 때, 장면 3 패널 도트)
- 장면별 적용 범위:
  - 장면 2 격자(기본): PJT 색 유지 — 격자에서는 PJT 구분이 우선
  - 장면 2 PJT 진입(enterPjt 후): 계층색 — 성운이 "무리지어" 보임
  - 장면 3 패널: 과제군 견본 표시 (5단계 변형이 미묘할 때 대응)
- hue 변형만으로 구분 안 되는 점 보완: 과제군별 원 크기/링 스타일 보조 유지
  (CONTEXT.md 원칙 "색만으로 전달하지 않는다" 유지).

## 절대 유지 (계약)

- `window.nebula` 시그니처, `nebulaCopy`, 페이로드 구조, `result.json` run_id 봉인.
- 셀렉터: `.step.active`, `#sky g.task`/`g.person`/`g.skill`, `#synthetic-mark` (live 상시).
- PJT 8색 팔레트 값 자체는 불변 — 변형은 파생 색 계산으로만.
- 인용·과제군 데이터는 그대로 — 색 계산만 추가, 데이터 계약 변경 없음.
