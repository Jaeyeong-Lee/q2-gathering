## 배경

Phase 1 더미 데이터를 실제 Gemini 임베딩으로 교체해본 첫 결과에서 발견된 것들.

- 임베딩: 98/150명 성공 (`gemini-embedding-2`, 3072차원, 분당 100요청 쿼터로 중단)
- 태그 추출: 매 실행 마지막 단계(consolidate_pool)에서 크래시 → **persons.json 태그는 여전히 100% 더미**
- charset/neighbors 누락 버그는 수정 완료 (template.html, build.py)

## 할 일

### 1. 유사도 표시 정규화

실제 임베딩 코사인 유사도는 0.93~0.97 좁은 구간에 몰림 (더미는 0.25~0.99).
템플릿 스프링 공식 `(1-w)*180+34` 기준으로 전부 짧은 엣지가 되어 네트워크가 중앙으로 뭉침.

- build.py에서 표시용 w만 min-max 재스케일 (neighbors.json 원본은 그대로)
- 완료 기준: 전체 뷰가 더미 때와 비슷한 퍼짐으로 렌더

### 2. 잔여 52명 임베딩 재실행

- 쿼터 리셋 후 `python scripts/embed.py` 재실행 (delay 들어가 있음)
- 이어서 `python scripts/similarity.py data/embeddings.json` + `python scripts/build.py`
- 완료 기준: 고아 노드 없이 150명 전원 이웃 보유

### 3. 태그 기능 재검토 (결정 필요)

**문제의식 (2026-07-12 논의):**
- 2단계 LLM 구조(인당 추출 151회 + 풀 동의어 정리 1회)라 파이프라인에서 제일 취약 — 이번 세션에서 유일하게 끝까지 실패한 단계
- LLM 자유 태그는 근거 설명이 불가 → 관객이 "왜 이 사람이 ○○형?"을 물으면 답 없음
- 유사도 네트워크(누가 비슷한가) + 워드클라우드(어떤 단어인가)와 신호 중복

**대안:** freq.json 상위 키워드를 인물 라벨로 사용 — LLM 0회, 결정적, 회고 원문으로 설명 가능

**결정 옵션:**
- A. 태그 기능 제거 (UI 태그 칩/필터/엣지 라벨까지, 004·006·008 폐기)
- B. LLM 태그 → freq 상위 키워드로 대체 (UI 유지, 데이터 소스만 교체)
- C. 유지하고 쿼터 확보 후 재실행 (기존 계획)
- D. (폴백) 태그 비활성화 — build.py에서 `tags: []`로 비우면 칩/필터/엣지 라벨이 전부 렌더되지 않음. UI 코드 수정 불필요, 한 줄. 하다 안 되면 무대 전날에도 끌 수 있는 안전장치.

권장: B — UI는 살리고 취약한 LLM 의존만 제거. 안 되면 D로 즉시 폴백.
