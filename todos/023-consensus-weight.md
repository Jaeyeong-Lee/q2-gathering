## What to build

워크숍의 투표·배치 결과를 성좌 지도의 별 속성으로 얹는다. **크기는 데이터(확산도), 고리는 사람
(워크숍이 고른 것)** — 관찰과 결정이 시각적으로 구별돼야 한다.

지금 저장소의 흐름은 전부 한 방향이다. 파이프라인이 산출물을 만들고 화면이 보여주는 데서 끝나고,
워크숍에서 사람이 정한 것을 **입력으로 되받는** 경로가 하나도 없다. 투표를 받는 서버가 있지만 그
결과는 어떤 지도에도 다시 실리지 않는다. 저장소의 용어 정의는 "전략은 사람이 채운다"고 말하는데,
사람이 채운 것을 받아 적는 산출물이 계보에 없다.

이 티켓이 그 고리를 닫는다. 실제 워크숍은 아직 열리지 않았으므로 **합성 투표 픽스처**로
증명한다 — 투표 형식의 샘플 파일을 넣으면 별에 고리가 생기는 것까지가 이번 범위다.

## Acceptance criteria

- [x] 투표 결과 파일을 읽어 별에 사람-입력 속성이 반영된다 (012에서 비워둔 자리를 채운다)
- [x] 데이터에서 온 속성(크기)과 사람에게서 온 속성(고리)이 화면에서 구별되고 범례에 명시된다
- [x] 투표 파일이 없으면 지도가 관찰만 있는 상태로 정상 렌더된다
- [x] 합성 투표 픽스처로 전후 스크린샷 2장을 뽑아 차이를 확인
- [x] pytest 통과
